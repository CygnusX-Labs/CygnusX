## BLOCKED 是什么

`BLOCKED` 表示某项验收所需的前置环境、授权或运行证据缺失，不是一个统一故障，也不能据此推断实现完全没有进展。当前主要缺口如下：

| 缺口 | 已知情况 | 解阻条件 |
|---|---|---|
| S5-C2 真实链路 | 之前的环境调查未能确认可用的专用 PG/Redis；Node 到 FastAPI 的回调和浏览器 E2E 未取得运行证据。 | 在获准的非生产环境提供专用服务身份和数据，完成双用户/项目权限、回调、撤权、浏览器刷新及 SSE 恢复验收。 |
| R3 运行与 UI | 当前有 Legacy/LangGraph 的隔离回归和 A1→A2 迟到 SSE 隔离测试；Research Agent 同进程断流续生成也有隔离测试。这不能证明部署服务链或完整页面工作流；进程重启后的生成恢复尚未实现。 | 使用真实配置的 Provider/API/SSE、数据库和 Node 回调运行，再以浏览器完成产品工作流并保存证据；另需设计并验证跨进程任务租约与崩溃恢复。 |
| S4 故障恢复 | 隔离测试覆盖部分事务失败、Broker 失败冷却、恢复扫描和公平性；真实 PostgreSQL 与 Broker/Worker/Beat 故障注入尚未完成。 | 使用专用实例验证并发、提交/投递边界、丢确认、Worker 重启、长期故障和恢复对账。 |
| G3-E2 执行隔离 | `DatasetIngestion` 可作为第一阶段 HTTP 准入来源；新的 admission/budget 表和严格 resolver 已通过隔离测试，但尚未接入 DatasetImport/Task 生命周期或 Supervisor。审批消费、真实 PG 并发、执行 epoch 和宿主硬限制仍未验收。原始多 Task 导入不能把整笔预算重复分配给每个 Task。 | 接通现有 processed-import Prepare/Approval 与新表，完成 Supervisor 和宿主限制，再在授权环境完成九项 HTTP 运行验收。源码证据见[G3准入审计](../../evidence/g3-e2-20261018/admission-source-audit.md)。 |
| 本地运行环境 | 2026-10-18 探针记录 Docker 连接被拒、loopback 监听受限、浏览器不可用、无可写 cgroup 根及可用的 `cgroup.kill`；没有获准的专用测试凭据。 | 换用具备所需能力的授权隔离执行环境，并重新采集当次探针；旧探针只代表当时环境。 |

S5-C 的原始调查还记录过 9 个 LangGraph 用例因旧 fixture 缺少 `_db` 而失败；后续 C1 报告记录了该问题的隔离修复与回归。因此不应把这 9 个历史失败简单当成当前唯一阻塞原因。upload 引用超时也有独立的 asyncio self-pipe `EPERM` 环境归因，需在允许本地 IPC 的环境重跑。详细边界见阶段报告。

## 推进顺序

1. 先读对应架构文档和阶段报告，选定一个具体验收项；不要用旧快照替代当前状态。
2. 准备获准的非生产运行环境，记录环境 ID、服务身份、代码/镜像版本、数据范围和清理责任。不要连接默认业务服务或生产数据。
3. 在环境内重跑该项并保留命令、退出码、原始日志、服务端关联和必要的截图；敏感信息应脱敏。
4. 只有证据直接覆盖该项的验收条件时，才更新矩阵状态；同步阶段报告、交接记录和 manifest 校验值。
5. 发布评审前保持运行门禁关闭。S6/S7 的准入须按其自身条件单独判断。

状态含义：`PASS_ISOLATED` 为隔离代码/测试证据；`PASS_RUNTIME` 为获准隔离服务上的运行证据；`PASS_E2E` 为带后端断言和浏览器证据的完整用户流程；`BLOCKED` 为必需条件当前不可用；`NOT_TESTED`/`SKIPPED` 不能算通过。矩阵子项通过不自动升级父项。
