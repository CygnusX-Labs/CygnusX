## 七、N-b 默认 CI 路径实施方案（待 CI 环境就绪后执行）

`tests/e2e/agentteams/test_live_foundation_e2e.py` 当前为 opt-in live 回归（`AGENTTEAMS_LIVE_E2E=1` + `OMICHUB_E2E_TOKEN`）。要把它接入 CI 默认路径，需要新增一个 CI job，在 GitHub Actions runner 上拉起完整真实栈并注入临时凭据。实施条件如下：

1. **Compose 服务矩阵**
   - 主栈：`deploy/docker/docker-compose.yml` 的 `web` / `db` / `cache` / `minio` / `minio-init`（worker/beat/flower/nginx 非必需）。
   - AgentTeams 侧栈：`deploy/agentteams/docker-compose.agentteams.yml` 的 `omichub-agentteams-bridge` / `omichub-agentteams-state`。
   - E2E-7/2/9 目前不依赖真实 Worker 执行，因此 `agentteams-acceptance` / `agentteams-production` profile 可先不加；后续扩展审批→执行→交付段（步骤 4）时再按需加入。

2. **外部网络和卷预处理**
   - 主栈需要 `omichub_net`、`omichub-sandbox-net` 两个外部网络；AgentTeams 栈还需要 `omichub_bridge_gateway`、`matrix-dev_default`。
   - 主栈需要外部卷 `omichub_embed`。
   - CI job 应在 `docker compose up` 前执行：
     ```bash
     docker network create omichub_net || true
     docker network create omichub-sandbox-net || true
     docker network create omichub_bridge_gateway || true
     docker network create matrix-dev_default || true
     docker volume create omichub_embed || true
     ```

3. **环境变量与 Secrets**
   - 常规运行：`POSTGRES_PASSWORD`、`REDIS_PASSWORD`、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`。
   - LLM/搜索能力：`AL_API_KEY`、`ARK_API_KEY` 等（Manager 回复链可能依赖）。
   - Bridge：`BRIDGE_STATE_STORE_URL` 可指向 compose 内 `omichub-agentteams-state:6379`；`BRIDGE_OMICHUB_SERVICE_TOKEN` / `BRIDGE_OMICHUB_API_KEY` / `BRIDGE_OMICHUB_INTEGRATION_TOKEN` 等需与主栈 `.env` 对齐。
   - 测试运行：`OMICHUB_E2E_BASE_URL=http://localhost:8000`、`AGENTTEAMS_E2E_BRIDGE_URL=http://localhost:8088/v1`。

4. **测试账号与 Token 种子**
   - 主栈启动并跑完 migration 后，在 `omichub-web` 容器内执行 `python scripts/init_demo_user.py` 创建演示账号。
   - 再用 `curl -X POST /api/v1/auth/login -d 'username=demo&password=demo_omichub'` 获取 `access_token`，导出为 `OMICHUB_E2E_TOKEN`。
   - `AGENTTEAMS_E2E_MANAGER_TOKEN` 对应 `bridge.env` 中的 `bioops-manager` token，需写入 GitHub Secret。

5. **建议的 CI 形态**
   - 先新建独立 workflow `.github/workflows/agentteams-live-e2e.yml`，触发方式设为 `workflow_dispatch` + 可选 `schedule: cron: '17 3 * * *'`（夜间回归），不要直接接入 PR 的 `pull_request` 触发器，避免 secrets 泄露风险和无栈 PR 阻塞。
   - 待该 workflow 在 staging 分支跑稳后，再评估是否并入 `.github/workflows/ci.yml` 作为默认 job（条件：secrets 可用、启动时间可接受、失败率稳定）。

6. **当前不推进的理由**
   - 上述依赖（CI secrets、compose 网络/卷编排、测试账号种子脚本）超出当前工作树可独立完成范围；在未验证的 runner 上直接改 `ci.yml` 会导致默认 CI 失败，反而降低基线可用性。
   - 因此本阶段保持 `AGENTTEAMS_LIVE_E2E=1` opt-in 门控不变，仅将实施方案落地到本文档，待用户提供 CI secrets / staging runner 后再执行。
