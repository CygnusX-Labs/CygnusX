## 1. 产品定位与体验目标

### 1.1 产品定位

CygnusX BioOps 是面向生命科学的受控科研 Agent 与可信计算交付平台。前端服务于数据发现、文件/样本管理、分析流程配置、Agent 协作、任务监控、结果报告、项目沉淀和科研证据追溯。

主品牌统一语气：可信、克制、专业、可追溯、具有星空与探索气质。品牌表达为：

- 主 Slogan：**FROM STARDUST, TO DISCOVERY**。
- 英文品牌宣言：*We are made of star-stuff.*
- 产品解释：**从数据发现与分析执行，到证据追溯与可信交付**。

避免将“星空感”表现为业务页处处大渐变、大动画。业务界面以高效清晰为首要目标，宇宙主题主要用于首页适量品牌展示、About 沉浸页、品牌细节和少量关键引导。

### 1.2 目标用户与典型任务

- 湿实验研究人员：找数据、上传文件、发起标准分析、阅读报告；需要明确的下一步操作和易懂的反馈。
- 生信工程师：高级配置、文件树、监控、下载、任务日志、分析结果；需要高信息密度与稳定交互。
- AI/Agent 研究人员：多模型会话、工具调用、审批、可溯源结果；需要可选的诊断信息而非默认噪声。
- 项目负责人：追踪项目、样本、任务、报告、证据与交付记录；需要全局上下文。

### 1.3 UX 北极星原则

1. **任务优先**：用户要做什么，比平台能展示多少功能更重要。
2. **相同语义，相同呈现**：任务状态、文件状态、报告状态不能跨页改含义。
3. **同一基础，多种工作区**：Standard/Explorer/Chat/Studio/Brand 分工明确。
4. **少打断、强恢复**：刷新、跳转、筛选和宽窄屏切换不应无意丢掉工作。
5. **来源可见**：数据来源、编号、时间、项目归属、执行任务与报告关系清楚。
6. **性能和可访问性不是装饰**：降低布局抖动、支持键盘、正确对比度。

## 3. Design System v1.0：唯一语义源与兼容策略

### 3.1 治理架构

采用 **现有 `tokens.css`（品牌与明暗基础值）→ `global.css`（语义别名/共享模式）→ `App.vue` Naive UI theme overrides → 已有基础组件/必要轻量 wrapper → 科研领域组件 → 页面布局** 的兼容治理链。**不重新造一套 Button/Input/Modal 行为**。Naive UI 仍是控件基础，Cx wrapper 只在统一语义、尺寸、测试钩子、ARIA 或跨页复用确有收益时建立。

样式职责建议：

- `tokens.css`：**已存在的品牌基础变量、明暗基础值**（权威）；可按兼容策略增加底层 Token，不直接替代 `global.css` 已有语义入口。
- `global.css`：**现存语义变量、共享交互类、辅助类、全局布局/特例**；`--arco-*` 仅为历史 CSS 别名（不是第二套组件库），`--kimi-*` 与 chat token 不得无验证合并；保持向后兼容。
- `chat-theme.css`：聊天域全局 Token 源，尤需保护 `--chat-input-bg`/`--chat-input-border`；`.kimi-layout` 的 `global.css` 局部覆盖目前与其并存，**不能直接抹除一个来源**。先通过主题/截图验证，再收敛单一可追溯映射。
- Studio：允许独立密度和背景层，但不另造全局 success/error/focus；**科研寻宝鼠在独立 iframe 内，未定位子应用源码前仅能改宿主**。
- 页面 scoped CSS：只负责页面布局、领域视觉和必要定制，尽量引用统一 token。

**迁移策略**：先引入兼容别名和清晰文档；试点两个页面；检查 Light/Dark；逐批迁移；最后才删无人使用的旧变量和补丁。提供自动化检索脚本或 lint 规则的**建议**，但不要求引入新依赖。若新增全局 Token/共享类/交互契约，按现行规范 §9 更新权威设计文档，同时检查 Codex Skill 引用副本是否需要同步。任何删除都需要引用搜索、回归与 diff 证据。

### 3.2 颜色语义规范

| Token 家族（逻辑命名，具体 CSS 命名按仓库统一） | 语义 | 要求 |
|---|---|---|
| `color.surface.base/card/elevated/subtle` | 页面、卡片、浮层、浅背景 | Light/Dark 完整映射 |
| `color.text.primary/secondary/tertiary/inverse` | 文本层级 | 普通内容满足 WCAG AA 目标 |
| `color.border.subtle/default/strong/focus` | 分割、输入与焦点 | 不仅用颜色表达状态 |
| `color.brand.primary/hover/active/soft` | 主操作、主品牌 | 蓝紫家族一致，交互态明确 |
| `color.status.success/warning/error/info` | 业务状态 | 与任务/报告语义绑定，不挪作纯装饰 |
| `color.agent.accent`、`color.treasure.accent` | 子模块个性 | 只能覆盖 accent 等允许项 |
| `color.chart.*` | 可视化系列 | 色盲可区分、图例和标记双重编码 |

**当前品牌与主题基线已在现行规范 §3.2 / §3.3 给出**：`--brand-primary` / `--arco-primary` 浅色基准 `#4C6FFF`、深色品牌值 `#7691FF`；浅色 `--neutral-bg: #F5F6FA`、`--neutral-card: #FFFFFF`；深色五级 `--surface-base/card/elevated/highlight/glass`（详见本文 §14）。不得用新的示例色板覆盖这些权威变量。科研寻宝鼠的绿色仅作为独立子品牌建议，需另审其源。

### 3.3 Typography、Spacing、尺寸参考

建议先以审计已提出的刻度作为评估基线，再按实际截图与浏览器检查微调：

| 语义 | 建议字号/行高 |
|---|---|
| Display | 28 / 36px |
| Page Title | 24 / 32px |
| Section Title | 18 / 28px |
| Card Title | 16 / 24px |
| Body | 14 / 22px |
| Small | 13 / 20px |
| Caption | 12 / 18px |
| Code/数字密集 | mono 13 / 20px，数字 tabular-nums |

- Spacing 采用现行规范 §3.4 的 **`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px`**；组内紧、组间松，不机械等距。
- **标准页规范默认 `--page-padding: 32px`**，窄屏可用 16px；静态审计显示 `.page-container` 实际常用 24px。此为**既有实现与规范不一致**，应先视觉基线比对、形成清晰的页面布局方案，再按页面安全迁移（不直接全局替换 24 为 32）。
- 控件建议建立 sm/md/lg 三档，对 Naive UI 的 size prop 作语义映射；点击目标参考至少 24×24 CSS px，密集触控优先接近 44×44 CSS px（需要与界面密度平衡）。
- 圆角建立 sm/md/lg/pill，阴影 0/sm/card/overlay；避免不同页面同时使用过多类似圆角。
- Z-index 集中命名：app、sticky、dropdown、drawer、modal、toast、global floating；避免全局浮球盖住确认框/输入栏。
- 动效只表达状态和空间关系；遵守 `prefers-reduced-motion` 和 `prefers-reduced-transparency`。

### 3.4 基础组件统一

**优先维护现有组件，不机械重建**：

- `PageHeader`：标题、副标题、breadcrumb、主/次操作、loading/error 插槽；覆盖常规业务页面。
- `EmptyState`：icon、title、description、primary/secondary action、compact/full 两种密度；`ReportEmptyState` 等领域变体优先通过参数组合复用。
- `CxStatus` / `WorkflowStatus`：统一显示层的 label、color、icon、tooltip、可执行动作；**后端枚举不变**。
- 表格优先**直接维护现有 `NDataTable` + 共享 CSS / 既有 TaskTable**；只有明确的跨页面重复契约才增加轻量 wrapper。现行规范 §33.2 强制所有列固定 `width`、`scroll-x` 为列宽和、百分比不换行、进度尺度归一化、短值列居中。
- `CxErrorState`：加载失败、权限不足、网络中断、内容不存在要可区分，并提供对应恢复。
- `CxPageContainer` 或 Layout：将边距、内容宽度、滚动责任设为显式配置，而不是依赖路由名和隐式 CSS。
- `ToolCard`、`ReportCard`、`TaskTable`：在原组件基础上增加清晰的变体契约，不进行无收益的 wrapper 套娃。

每个公共组件写明 Props/Slots/Events、键盘行为、Loading/Empty/Error、Light/Dark、响应式、使用示例和测试覆盖。未经搜索验证不要随意改名影响全站引用。

### 3.5 深浅主题和兼容验收

审计指出主题 Store 支持 dark/light，默认值报告为 dark；截图展示浅色外观，具体运行偏好尚需核实。**不得以截图改变默认主题**。现行规范 §3.3 定义深色五级 Surface；Light/Dark 都必须按规范完整通过。Naive UI 颜色/圆角仅通过 `App.vue` 的 `themeOverrides` 管理，不能在页面中重新定义一套 Provider。

## 4. App Shell、导航、布局和滚动优化

### 4.1 导航信息架构

当前 `topNavItems` / `mainNavItems` 分离。建议建立统一 **Navigation Registry**，再投影为 top/side/mobile/compact，**不改变已有真实路由、权限和功能开关**。先输出现状映射，处理同功能重复入口和激活态冲突。不要把权限判断只挪到前端；必须沿用 `modulesStore.lockedModuleForPath`、后端权限及 `disabled_modules` 机制。

推荐供产品评审的导航分组（最终基于已存在路由和权限落地）：

| 分组 | 功能候选 | 原则 |
|---|---|---|
| 工作台 | 首页、仪表板、项目管理 | “继续工作”与“全局概览”分工明确 |
| 科研发现与数据 | 科研寻宝鼠、数据管理、数据库、数据下载 | 面向数据生命周期 |
| 分析与交付 | 分析中心、任务中心、流程监控、报告中心 | 面向任务生命周期 |
| 智能协作 | AI 助手、AI 工作台 | 明确通用问答与可执行工作区边界 |
| 科研工具 | 生信工具箱、知识库 | 高频快捷工具与资源 |
| 系统 | 用量统计、Agent 能力、设置、关于 | 低频项归组，不强塞顶部 |

顶部导航应优先承载产品大区或快捷切换，侧栏承载层级入口；不得维持两份彼此漂移的配置。保留 compact sidebar 的键盘聚焦、tooltip 与活跃状态，手动折叠与窗口自动折叠应有明确优先级。移动端侧栏改抽屉，不与主内容争宽。保留浏览器前进/后退及深链刷新。

### 4.2 布局类型：区别化而非一刀切

| 类型 | 覆盖页面 | 布局约定 |
|---|---|---|
| `StandardPageLayout` | 首页、仪表板、任务、报告、项目、数据库、下载 | PageHeader、标准间距、主操作、空/错态 |
| `DataExplorerLayout` | 文件管理及适合的资源浏览 | 左树 + 主区 + 可收起详情/活动栏，主区优先保证宽度 |
| `ChatWorkspaceLayout` | AI 助手 | 会话栏 + 消息区 + composer；消息阅读区有合理最大宽度 |
| `StudioWorkspaceLayout` | AI Studio | 三栏/可调宽、工具与待审批区，窄屏退化为 Drawer/Tab |
| `MonitorLayout` | 流程监控 | KPI + 实时任务 + 事件/错误区，支持独立滚动 |
| `ImmersiveBrandLayout` | About、部分品牌场景 | 深空视觉，内容优先可读、减少动效可降级 |
| `EmbedHostLayout` | 寻宝鼠宿主 | iframe 尺寸、loading/error、父级滚动和响应式协定 |

先使用路由 meta 明确每类布局和滚动责任。`fullscreen` 保持兼容，可逐步改为更清晰的 `layoutVariant`（名称仅建议），避免改动所有路由。`html/body/#app` 的高度/overflow 方案需结合实际嵌套容器验证后再改，不允许直接删除所有 `overflow: hidden`。

### 4.3 Header、浮层与滚动

- 提取可复用的 Header/sidebar 宽高 Token；处理顶部导航、搜索、消息通知 `99+`、额度、帮助入口在小屏的拥挤风险。
- 聊天/Studio 内部二级 header 是“会话工具栏”，与全局 App Header 的职责分开；避免重复返回、重复主标题和冲突的固定定位。
- 上传浮球、全局 AI 入口不得遮住按钮、表单底部或确认弹窗；有可收起或安全区域，移动端尤其注意。
- 各布局明确唯一主滚动容器；弹窗只锁该锁的滚动；flex 子项按需要 `min-height:0`、`min-width:0`，图表不越界。
- 面包屑、页面标题、操作区对齐；保留现有链接语义和键盘导航。

4. 访问 About 不能让用户丢失之前折叠的 Sidebar 偏好；动效支持 reduced motion/transparency。
5. GitHub、进入控制台/分析中心等按钮应对应有效链接，并正确处理移动端。

**验收**：中英文标语准确、桌面/手机均完整展示；无明显低对比度文字、无动效导致操作障碍。

## 6. 跨模块科研工作流与状态统一

### 6.1 已有链路：保留并验证

| 链路 | 审计中已确认的事实 | 必须回归 |
|---|---|---|
| 公共数据 | 下载提交会跳转 `/tasks/:id` | 下载成功/失败、任务深链、结果可见性 |
| 已有文件分析 | `FilesView` / `FilePickerModal` 会传递 `file_id`；`FlowSubmitView` 创建任务并跳详情 | 文件选择、分析参数、执行任务、任务回跳 |
| 任务到报告 | `TaskTable` 根据 flow 去工具结果或 `/reports?taskId=` | taskId 保留、筛选、报告预览 |
| 报告到 Studio | ReportsView 可使用报告创建 Studio session | `report_id` 来源、回跳、会话可追溯 |
| 项目关联 | project detail `projectId`，AI/Studio 具有 `project_id` 传递路径 | 不同入口下项目归属一致性 |
| Agent | SSE、工具调用、审批与进度卡已存在 | 无回归、错误反馈和中断恢复 |

上述“代码存在传递”不等于完整 E2E 已成功，需在运行环境验证。数据下载后自动入库、寻宝鼠到下载、跨入口自动项目识别等尚缺完整证据，必须先核查，不得为了界面显得闭环而模拟成功。

### 6.2 统一显示状态，不改后端权威语义

新增 `TaskDisplayStatus` / `ReportDisplayStatus` 类型或等价 mapper（确切位置由项目架构决定）：

| 前端展示语义 | 示例原始值（仅说明，需核实后端枚举） | UI 行为 |
|---|---|---|
| 待处理 | pending / queued | 显示等待；不假装运行 |
| 运行中 | running / processing | 显示进度/实时事件 |
| 已完成 | success / completed | 提供结果/报告入口 |
| 失败 | failed / error | 错误原因、符合权限的重试动作 |
| 已取消 | cancelled / canceled | 显示终止，不伪造成功 |
| 需确认 | approval_required / waiting_user | 强调明确的可执行确认流程 |
| 未知 | 非预期状态 | 安全的“状态未知” + 原始值诊断（高级模式） |

**以上只表示显示层目标，不是断言这些值都已经真实存在**。先梳理真实 API enum、大小写、i18n、历史数据，再写转换表和测试，不要丢失未知状态。

### 6.3 项目上下文和 Provenance

- 页面显式显示当前项目/会话/任务/文件/报告的归属；可跳转至相应详情，尊重权限与历史默认项目策略。
- 优先沿现有 route query、params、Pinia store 和 API DTO 传递 ID；只有发现经复现的上下文丢失时才新增统一 ProjectContext adapter。
- 推荐标准关联展示：**来源（GEO/SRA/用户上传）→ file_id → analysis task_id → report_id → studio session_id → project_id**。缺失项展示“未关联/未知”，不得生成假的证据链。
- 对数据库来源、论文引用、AI 工具调用分别记录可见来源链接与时间戳的展示约定，保持只读可信源理念。
- 跨页面的“返回”按钮应返回有意义的上游位置；深链直接访问时回退到合理默认页面。

## 7. 工程质量：响应式、可访问性、性能与错误恢复

### 7.1 设备测试矩阵（必须真实浏览器验证）

| 视口 | 主要检查 |
|---|---|
| 1920×1080 | 最大宽度、留白、工作区多栏、图表撑开 |
| 1440×900 | 主力桌面布局、首屏 CTA、控件密度 |
| 1280×800 | 侧栏/三栏挤压、表格最小宽度 |
| 1024×768 | 壳层自动折叠边界、横向滚动 |
| 768×1024 | 抽屉/折叠阈值临界、触控目标 |
| 390×844 | 单栏与 composer、弹窗/输入操作不遮挡 |

每一主要业务工作区在 Light/Dark（确实支持时）都要检查：水平溢出、双滚动、fixed/sticky 遮挡、中文长文本、图表、表格、拖拽面板。禁止仅靠代码审查声称响应式“通过”。

### 7.2 空/加载/错误体系

将“无数据”“筛选无结果”“用户无权限”“请求失败”“服务断线”“尚未创建资源”六种情况分开，不共用一个笼统占位符。空状态应提供准确下一步行动，按钮必须可执行且权限允许。loading 优先保持容器稳定、避免 CLS；错误提供重试、返回或诊断信息，禁止无声失败。

### 7.3 可访问性

- WCAG 2.2 AA 作为目标；普通文字对比度原则上 ≥4.5:1，大文字/必要非文本控件参照相应标准；对状态色同时提供文本或图标。
- Focus visible、跳到主要内容的 skip link、键盘 Tab 顺序、Enter/Space、Escape、dialog focus trap 与恢复。
- 图标按钮有可访问名称；表单 label / error message 关联；文件树、表格、聊天流按合适语义标记。
- 支持 `prefers-reduced-motion`、`prefers-reduced-transparency`；评估 `forced-colors: active`，不要无条件覆盖系统高对比度。
- 先选择关键流程做 axe/人工键盘测试；若现有工具不足，以可复现手测证据代替，不擅自新增测试库。

### 7.4 性能与稳定性

- 现有路由动态 import 已存在（审计提到约 72 个路由级入口），不要因重构变成全量同步 import。
- 优先检查 Studio/Monaco、CodeMirror、Plotly、ECharts GL、大文件树、长 AI 消息和高频 WebSocket 的实际首屏/交互成本。
- 按实际瓶颈考虑 memo/虚拟列表/懒载入；不要无证据滥用虚拟化，避免破坏滚动、复制、锚点和聊天流。
- 检查 `AppErrorBoundary` 与动态 chunk 失败真实交互；若需 router.onError，设计“可恢复、有限重试、防循环刷新”的方案，并补测试。不要在加载错误后强制无限 reload。
- 建议记录优化前后 bundle/chunk、关键页面首屏、交互延迟、长会话性能；具体预算应由当前基线决定，不能编造提升百分比。

## 8. 分阶段实施计划：整份文档一次交付，代码按批次落地

> 阶段可在同一个 Codex 总任务下连续执行，但**每个阶段有独立验收门槛**；如仓库已有用户修改或测试失败，先定位并避免覆盖。除明确阻塞外不要每做一步都要求用户重新提供提示词。

### Phase 0｜基线、保护现场、补证据

**目标**：建立可信改造前状态。  
**动作**：阅读约定与审计；`git status`；确定 workspace 与脚本；确认审计回写文档的 diff；运行现有可安全执行的 typecheck/test/build（按实际 package scripts）；用已有 Playwright/浏览器环境建立关键视口截图；记录主题、空状态、权限和主链路。  
**产物**：baseline 文件/测试输出、改造前截图索引、待证实问题列表。  
**门槛**：已知基线失败不能隐瞒，区分“既有失败”和“本次引入”。

### Phase 1｜基于现行 Token 与 Naive UI 主题的兼容治理

**目标**：建立唯一语义规范而不破坏现有模块。  
**动作**：清单化颜色/字号/间距来源；建立兼容 token 映射；调整 Naive overrides；先迁移 Dashboard 与 Tasks 两个试点；确保 Light/Dark；清理可证明无用的局部重复声明。  
**触碰范围**：`tokens.css`、`global.css`、主题入口、Dashboard/Tasks 及必要公共组件。  
**验收**：两试点布局/状态正常，旧页面不被全局覆盖，新增 token 命名清楚且可复用。  
**回滚**：保留旧变量映射，按文件组拆小 diff。

### Phase 2｜App Shell、导航和 Layout Contract

**目标**：统一外壳与滚动而保留各工作区独特性。  
**动作**：Menu Registry → top/side/mobile；显式 Layout 变体；Header/Sidebar 尺寸与 PageHeader/EmptyState 标准；解决 24/32px、0 padding、多滚动责任冲突；先迁移 Home/Dashboard/Tasks/Reports 等常规页。  
**验收**：权限/feature flags/active path 正确，1024/768 临界视口正常，AI/Studio 不因壳层更改而错位。  
**回滚**：旧 meta/导航配置可兼容一段时间。

### Phase 3｜数据发现与文件生命周期

**目标**：优化 `/files`、`/database`、`/downloads` 和寻宝鼠宿主。  
**动作**：文件 Explorer 栅格、上传状态、数据库版本与资源状态、下载表单/摘要/进度；按真实 API 验证下载→任务→文件路径； iframe 宿主稳定性。  
**验收**：上传/下载/目录/文件 ID/API 入口、旧路由别名无回归。  
**注意**：寻宝鼠子应用源码未取得前，**只能优化宿主**，内部问题记录为单独待办。

### Phase 4｜分析、任务、监控、报告与项目

**目标**：让数据→任务→报告→项目的显示与状态一致。  
**动作**：共享 status mapper、TaskTable/Workflow widgets/ReportCard 展示语义；项目/报告深链；修复 AgentTeams 失效路由；报告 canonical flow 展示值；统一空/错/载入；任务/报告回链。  
**验收**：任务 ID、report ID、project ID、参数与状态保真，工作流 E2E 至少覆盖成功与失败路径。

### Phase 5｜按现行 §18/§35–§37 保护协议的 AI 助手与 Studio 工作区治理

**目标**：保留 Agent 功能、改善阅读和操作。  
**动作**：区分默认与高级诊断 UI；工具/审批状态；消息宽度；任务理解卡与待处理区遮挡；Studio 三栏与窄屏策略；必要时按明确边界拆大 SFC。  
**验收**：AI SSE、模型选择、工具审批、附件、会话保存、报告联动、长会话交互无回归。  
**回滚**：每次只迁移一个 panel 或一类卡片，保留旧协议与组件签名。

### Phase 6｜工具箱、品牌 About、完整一致性收尾

**目标**：统一工具入口、补充品牌层级与可访问性，完成全站验收。  
**动作**：ToolCard/工具详情 Shell；About 品牌层级与动效；全站颜色/字号/空状态/焦点审查；重复 token/样式继续收敛；更新前端架构与设计规范。  
**验收**：14 页清单、6 视口、Light/Dark、键盘及主要业务 E2E 完成；遗留事项公开记录。

### 8.1 推荐最小可审查变更批次

| 批次 | 内容 | 主要风险 | 最低验证 |
|---|---|---|---|
| B01 | baseline + 只读截图/基线文档 | 低 | 无源码被意外修改 |
| B02 | token 兼容层 + Naive overrides | 中 | Light/Dark + Dashboard/Tasks |
| B03 | 统一基础空/错/页头组件 | 中 | 组件 API/快照回归 |
| B04 | Navigation Registry + 壳层 padding/scroll | 高 | 权限、移动/桌面、AI/Studio |
| B05 | Home/Dashboard/Tasks/Reports 视觉迁移 | 中 | 页面截图 + 路由 |
| B06 | Files/Database/Downloads | 高 | 上传/任务/参考资源 |
| B07 | Task/Workflow/Report/Project 状态和回链 | 高 | E2E/ID 传递 |
| B08 | AI 助手与 Studio 分层治理 | 高 | SSE/审批/输入/会话 |
| B09 | Tools/About/无障碍与性能 | 中 | 工具计算、Brand 动效 |
| B10 | 文档、测试矩阵、收尾与遗留清单 | 低 | 全站回归报告 |

批次只是建议切分。如果一次 Codex 会话无法完成，输出每批可复制的后续任务指令；**不允许在未经验证的前提下强行压成一个大改动**。

## 9. 必须验证的测试矩阵

### 9.1 仓库门禁

先查看 `frontend/package.json`，按真实已有脚本执行类型检查、lint、单元测试、build、E2E；不假设脚本一定名为 `npm run type-check`。若环境未安装依赖或无法访问服务，记录原因与已完成的静态检查，不盲目安装/升级。

### 9.2 14 页视觉回归

为每页建立“改造前/改造后”截图索引：页面路由、分辨率、Light/Dark、登录角色、数据状态、采集时间、截图文件路径。关键至少 1440×900 和 390×844；App Shell/Studio/文件管理应覆盖六视口。视觉 diff 需要人工审查，不能只用像素差判定好坏。

### 9.3 功能链路 Smoke/E2E

1. 登录 → 首页 → 侧栏 → 仪表板 → 导航返回。
2. 科研寻宝鼠宿主加载、错误提示和重试；子应用内部仅在取得源码后测。
3. 文件树浏览 → 选择/上传文件 → FilePicker → 分析提交（测试环境模拟/隔离，避免生产任务成本）。
4. 数据下载：编号校验 → Dry Run → 提交（测试环境）→ `/tasks/:id`。
5. 分析任务：运行中/成功/失败/取消（仅实际支持的状态）→ 详情/报告。
6. 报告 `?taskId=` 深链 → 预览/下载 → Studio → 回报告。
7. 项目列表 → 项目详情 → 任务/会话/报告；AgentTeams 下线入口安全处理。
8. AI：创建/切换会话 → 发送消息 → 工具/审批 → 中断/错误 → 恢复。
9. Studio：模型/模式切换 → 待处理问题 → 工具输出/产物 → 保存/重新进入。
10. 生信工具箱代表工具：输入 → 计算 → 结果/导出，验证无算法回归。

### 9.4 典型数据状态

每页至少覆盖：空 / 正常 / 加载中 / 网络失败 / 无权限（有对应机制时）；跨页 ID 需真实有效；超长中文、英文、URL、样本编号、多字节文件名至少覆盖一组；不得用虚构科研结果充当真实数据。

### 9.5 回归阻断条件

出现以下情况必须停止相关批次并恢复/修复后再推进：

- 鉴权、权限或功能开关绕过。
- 任务提交参数、文件 ID、项目 ID、报告 ID 丢失或改变。
- AI 工具审批、安全确认被移除/误触发。
- 任一关键页面无法进入、主要 CTA 无效、路由死循环。
- 大范围主题错乱、重要文字不可读、移动端输入被遮挡。
- 本批次引入的 typecheck/build/test 失败且无法定位。

## 10. 量化指标和验收标准

| 维度 | 目标（按证据验收，非宣称现状） |
|---|---|
| 设计一致性 | 新迁移页面使用同一语义 token；少量有意差异有设计说明 |
| 主题覆盖 | Light/Dark 在关键组件、14 页无明显硬编码逆色问题 |
| 导航 | 顶部/侧栏/移动端从单一注册源投影；原有权限和深链不变 |
| 布局 | 6 个视口无阻断性横溢/遮挡；工作区的滚动责任清晰 |
| 空/错态 | 主要页面区分无资源、无结果、加载失败、无权限并有有效下一步 |
| 科研链路 | file_id/task_id/report_id/project_id 在已有链路中可追溯且不被视觉重构修改 |
| AI/Studio | 工具审批、SSE、输入/待办、会话切换与保存不退化 |
| 代码健康 | 高影响范围的样式重复、硬编码与无用 `!important` 分批下降；不能以计数为唯一目标 |
| 性能 | 对重点页面采集前后可比实测数据；不得明显恶化核心交互 |
| 可访问性 | 关键路径键盘可完成，Focus 清晰，必要文字对比度符合目标 |

**阶段完成定义（DoD）**：完成实现 + 代码差异说明 + 自动/人工验证记录 + 关键截图 + 无阻断回归 + 可回滚边界 + 更新对应设计/架构说明。未满足任一项，必须标记“部分完成”，而不是“已完成”。

## 16. 强制继承的业务 UI 与数据可视化契约

### 16.1 NDataTable / 任务进度 / 用户显示（不可误改）

适用于 Dashboard 最近任务、任务中心、AgentTeams Case、BLAST、管理配置、工具表格等。

1. `NDataTable` 每个可见列明确固定 `width`，`scroll-x` 等于列宽之和；表格本身 `width:100%`，不限制自身 `max-width` 而留下卡片右侧空白。列宽总和超出容器时仅在表格包装层横向滚动。
2. 标识符长文本用 `ellipsis + Tooltip`；短值/离散状态列 `align:'center'`，**进度列不居中**。
3. 进度不允许 `100 %` 换行；已有两类方案：（a）`.n-progress-graph {min-width:0}` 配合 indicator nowrap；（b）关闭内置 indicator、`renderTaskProgress` 单独使用 44px 固定数值文本。以当前权威组件的实际实现为准，避免同时叠加两套输出。
4. 兼容多来源 `0–1`、`0–100` 进度尺度，现行 `pct()` 规则 `Math.round(n > 1 ? n : n*100)` 是前端的遗留兼容兜底；新增代码应优先采用已有已测试归一化函数，并为 `0,0.45,1,45,100,null,NaN,负数,超界值` 提供测试。**不改后端持久化尺度**。
5. 用户列调用 `src/utils/displayName.ts` 的 `displayName({nickname,username})`，昵称优先、用户名兜底；不可拿 UUID 或虚构用户充当演示数据，确无资料显示“未知用户”并标记待核验来源。
6. 用户专属文件路径显示调用 `src/utils/userPathDisplay.ts` 的 `formatUserPath()`；日志自由文本调用 `redactUserHomePaths()`。**原始路径仅用于 API 请求，不能把存储根路径显示、复制或导出给普通用户**。不要在组件中另写 `replace()`。
7. 真实表格采用明确 `row-key`、可重复调用的 `load*` 函数与查询状态；刷新保留筛选、分页、选中（有效时）和滚动，不用 `window.location.reload()`。
8. 加载 Skeleton、局部 Spin、部分失败且保留旧数据、权限态和空数据引导需覆盖；禁止“按钮能点但只 toast 对接中”的虚假功能。
9. 选择表格虚拟化必须满足**稳定行高/可预测容器高度**；不满足时使用后端分页，不机械因超过 100 行而启用不稳定虚拟滚动。
10. 页面嵌入的卡片表格遵循 `global.css` 不透明 Surface、表头/表体分隔、分页 footer 实体底色；不在局部添加半透明表格覆盖。

### 16.2 科研图表（ECharts/Plotly）

- ECharts (`vue-echarts`) 优先用于通用统计图及现有火山图、曼哈顿图、热图 processor；Plotly 用于既有特殊交互/导出场景。不要为统一风格替换图表引擎。
- 图表数据处理独立为 `src/utils/*Processor.ts` 纯函数：无网络请求、无全局 Store 副作用。
- 图表系列使用 `--kimi-chart-1` 至 `--kimi-chart-6`；坐标、图例、提示框、网格线消费现有主题语义，主题改变需刷新图表选项。
- **Canvas 严禁直接把 `'var(--some-token)'` 字符串传进 ECharts option**；必须在 DOM 中先经 `getComputedStyle(...).getPropertyValue(...)` 得到实际色值后交给 ECharts，并在主题变化后重新解析（`TrendChart.vue` 模式）。DOM style 可以使用 CSS `var()`。
- `TrendChart.vue` 既有双 Y 轴（任务柱/样本折线）契约不因“统一趋势图”退化为单轴；空数据不能画一条误导性的 0 趋势而不解释数据来源。
- 容器使用 `autoresize` 或 `ResizeObserver`，窄屏保留最小可读高度，必要时水平滚动。
- 大点数按规范 §13 分级：>500 采样/large，>5000 考虑 `dataZoom` / 后端聚合；每种生信图表保留其科学语义、图例、阈值和导出。
- 可访问性至少有 `aria-label` 或相邻摘要表格，不以颜色作为唯一科学差异编码。

### 16.3 样本、下载与科学状态

- 下载/分析/报告/项目卡只在显示层映射状态，后端的 `pending/queued/running/success/completed/failed/cancelled/generating` 等权威值保留；不为了统一颜色而修改类型或重写任务状态机。

## 17. AI / Studio / Agent 保护区：最高风险回归清单

> 本章引用现行规范 §5.0、§14、§18、§19、§35–§37。任何涉及 `AgentWorkspace`、`AgentSandbox`、`KimiChatInput`、`KimiMessageItem`、`StudioView`、Agent store、SSE/WS composable 的 PR 均须满足。**纯视觉任务默认不改协议层。**

### 17.1 AI 助手产品目标（现行规范 §35，逐项验证现状）

**空会话**：助手身份 → 输入区 → 4–6 个有真实行为的快捷任务 → 最近会话/文件/任务 → 低频高级选项。输入区为视觉主操作中心，避免大面积无作用留白与营销化横幅。

**活跃会话**：助手工具栏 → 可滚动消息区 → 底部输入 Composer。切换布局不丢草稿/附件/模型/思考模式/当前会话；用户向上阅读时不强制拉回底部，保留“回到底部”。

**导航三层职责**：平台 Header 管产品/账户/通知；全局 Sidebar 管核心模块；AI 侧栏管新建/历史会话/会话工具。AI 侧栏移动端使用 Drawer，折叠图标必须带 Tooltip；不要把三个导航都变成永久展开。

**快捷任务**：使用结构化配置（`prefill / configure / navigate / select-file`），点击必有实际行为；无能力则禁用并解释；不以不同颜色代替语义。

**助手/工作台边界**：普通 AI 对话默认收纳 Token、路由和复杂诊断，专业模式允许展开；Studio 是高密度专业工作区，不强行收缩为单列对话页面。

**实施状态**：§35–§36 中“建议组件边界”和“执行提示词”是目标/提案，Codex 应先确认哪些已存在；不允许只根据文档就在仓库中重复新建同名组件。

### 17.2 流式状态机和连续会话（阻断级）

- `useChatStream` / `useAgentChatStream` / `useStudioRunStream` 中流式入口守卫 `isStreaming`、AbortController 的清理必须覆盖 **done/error/HTTP 非 2xx/超时/重试耗尽/AbortError/提前 return**；原则上使用 **`try/finally`**。diff 若删除已有 `finally` 却未覆盖全部分支，拒绝合并。
- 流式消息无法获取到后端时不展示“模型空响应”来掩盖前端没有发出请求；区分本地重复发送守卫、网络错误和模型真正空输出。
- 任何涉及 send/stop/retry/composable 状态的改动必须加入**同一个 composable 实例的连续第二次发送**测试：第一次 done 后 `fetch` 第二次确实调用。
- 网络中断：保留已收到的正文、工具状态；允许合理的重连/重试并明确状态，不把已输出内容清空。
- SSE 发送、临时 ID 回填、终态合并与历史恢复必须保持原行为。`KimiChatInput` 内外背景一致，不能单纯替换组件导致草稿和附件丢失。
- WebSocket 生命周期沿 §14 检查连接、心跳、重连、可见性、销毁；不因为菜单视觉重构产生重复连接与僵尸监听。既有心跳/退避协议改变需独立审计，不做顺带修改。

### 17.3 Plan、参数确认、审批和工具卡（阻断级）

- `StudioPlanTimeline.vue` 的 Plan 卡片**属于输入框上方附着面板**而非消息气泡：左右边界必须与 `KimiChatInput` 对齐，保持 8px 间隔；`pending/in_progress/done`、`X/N` 和折叠行为需要完整状态。
- 计划数据来自 `update_plan` / `sandbox_meta.plan` / SSE；重开会话须恢复计划，成功写操作对应自动推进规则由现有后端负责；本轮前端不得重写 Plan 推进状态机。
- 完成自动折叠一次，手动展开后不再次自动收起；折叠控制有 `aria-expanded`/`aria-controls`；布局改变时不可遮挡输入。
- `ask_user` 卡片（`AskUserCard.vue`）要显示多选项交互/自由输入/跳过、推荐顺序、回答后折叠；不允许改成纯文案气泡。
- `McpToolCallCard` 默认折叠，展开区有限高（summary 220px、JSON 200px），避免长结果撑开整个对话。
- `ApprovalCard`、待处理问题浮层只优化展示位置与遮挡，**确认语义、权限、参数和提交动作保持不变**；窄屏下不得压盖输入框或发送按钮。

### 17.4 历史重载与研究产物（阻断级）

- `agentHub.ts` 的 `loadSessionMessages()` 使用 `metadata_json.tool_invocations` 重建工具卡，并通过 `metadata_json.timeline` 还原“文本→工具→文本”交错顺序；不得因消息 UI 重写而改为“文本全部置顶、工具全部放最后”。
- `ui_payload`、`result`、`arguments`、`mcp_server`、`stdout/stderr` 的读取须兼容旧记录与截断哨兵 `{_cygnusx_payload_truncated:true}`；不能对缺失 payload 直接崩溃。
- 图表和产物按 §37 存为 artifact manifest；新文件/图片/表格不只放一次性 DOM 或仅有内联预览。消息产物统一由 `MessageArtifactGallery`，Studio 右侧由 `StudioArtifactsPanel` 预览，避免重新做第二套下载入口。
- `artifact_manifest_version`、`artifact_manifest` / `artifacts`、`path/size/sha256/url/kind/source` 保留已有协议。`path` 为相对路径；旧会话没有文件只做兼容降级，**不能凭空宣称已恢复**。
- stdout/stderr 按原始换行用 `white-space:pre-wrap` 渲染，长行折行及限高滚动；不能交给 Markdown 普通段落吞换行。
- 若必须改工具调用持久化，需显式覆盖后端 ChatService 的 **legacy 与 LangGraph 两条路径**；但**本轮默认禁止后端改动**，发现缺陷后单独提议和申请授权。

### 17.5 文件/PDF/图片预览与路径显示

- PDF 不在普通聊天卡内 `<iframe>` 直接展示，而是在 `NModal` 里查看并用 `#toolbar=0&navpanes=0` 隐藏原生工具栏（浏览器支持情况需实测），由自定义按钮触发下载/打印。
- 图片缩略图可点开 25%–500% 放大和下载；使用已有 `MessageArtifactGallery`、`StudioArtifactsPanel`、`FilePreviewModal` 能力，优先复用，不重新造轮子。
- 打印用 `src/utils/blobPrint.ts` 的 `printBlobUrl()`；文件下载需保留权限与统一接口约束。
- 这条限制只针对 **PDF 文档预览**，不意味着要删除寻宝鼠页面为独立应用提供的 iframe。

### 17.6 智能体选择弹窗

沿用 `AgentWorkspace.vue` 的“搜索 + 筛选 chips + 分组卡片 + 最近使用”交互（现行规范 §5.0）：宽 `min(1120px,92vw)`、最大高度 `min(72vh,860px)`，头尾固定、中间列表滚动，键盘 `↑/↓/Enter/Esc`，取消仅关闭，不新增副作用。能力 chips、分组与最近使用 ID 的存储规则不得在视觉更新中静默改写。

### 20.4 构建产物和真实运行结果

- 构建成功不等于样式生效。Vite 可按路由拆分 CSS chunk，检查改动选择器是否落在**实际路由分包**（规范 §31.5）；不能只检查主 `index-*.css`。
- 对本地开发/测试环境检查 JS/CSS 加载、浏览器 Console、无 404 chunk、缓存问题；正式环境部署需要另行授权，本任务**不部署/不碰 nginx/不 rsync**。
- 文档标记“静态确认/实测确认/待实测”三种证据层级；不能把静态判断升格为“所有视口已通过”。

### 20.5 阻断合并的回归类型

1. 任意核心页面不可达、白屏或动态 import 故障无法恢复。
2. 任务参数/权限/路由/项目归属被样式重构改写。
3. 聊天首次成功、第二条被吞；stop/retry 永久锁死；SSE/WS 僵尸连接。
4. Plan 卡片丢步、状态错误、审批误触发、`ask_user` 选项消失。
5. 图表显示黑柱、进度显示 1000%、表格横向空白或百分比换行。
6. 用户普通视图出现平台用户 Home 的原始绝对路径、真实安全敏感字段泄露。
7. PDF/图片不能预览或下载；历史工具卡/产物重载丢失（既有可用内容）。
8. 深色主题大片色块不匹配、卡片内容被层叠背景挡住、导航失焦/不可点。
9. 将真实 0 数据替换为编造 demo 指标；把未实现按钮改成假点击成功。
10. 未跑测试却宣称“所有测试通过”。
