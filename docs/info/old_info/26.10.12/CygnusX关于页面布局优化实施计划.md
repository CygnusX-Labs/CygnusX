# CygnusX「关于」页面布局优化实施计划（活文档）

> 文档性质：跨轮累积的活文档。本轮（2026-10-13）为第 1 轮：布局嫌"难看、很空"的整
> 体优化。后续新吐槽/新需求追加为新 Part，不另起文档。
> 任务类型：已有页面视觉/布局优化（**改已有页面，不是重新设计**——2026-07-22 用户明
> 确纠正过的边界）。
> 施工方式：用户把各阶段提示词粘给编码 Agent（kimi code / Claude Code 等），验收权在
> 用户手里，不接受编码 Agent 自报通过。

---

## Part 1　背景与目标

- **页面**：CygnusX 平台「关于」页（路由 /about，桌面端 2560px 宽屏截图 3 张为现状基准）。
- **用户吐槽**：布局不喜欢，感觉很难看、很空。
- **目标**：在不推翻现有实现的前提下，让关于页从"三屏概念卡片 + 一句话"变成有信息
  密度、有节奏、有落点的页面；消灭大而无当的空旷感。
- **硬约束**：
  - 不推倒重写、不改路由、不动功能逻辑、不引新依赖（确有必要先说明理由）；
  - 星空/宇宙视觉基调（深蓝紫渐变、star-stuff 文案、"召唤星际猫咪"悬浮钮）必须保留，
    风格与首页一致；
  - 响应式不破，移动端无横向滚动；
  - 动效只用 transform/opacity，尊重 prefers-reduced-motion。

## Part 2　现状诊断（逐条问题清单）

依据 2026-10-13 三张截图，"空"和"难看"是以下 7 条叠加的结果：

### 2.1 容器过窄，宽屏两侧大面积裸奔（"空"的直接来源）

所有区块（Hero 文案列、三张理念卡、BioOps 孤盒、生态四卡、Vision 引言）都集中在屏
幕中间一条窄栏（目测 max-width 约 860~1100px）。在 2560px 屏宽下，每屏两侧各空出
约 1/3 宽度，且背景是同一张无变化的深空渐变——留白没有用视觉元素组织起来，成了真
的"空白"。

> 设计依据：留白是功能性元素，应当"围出焦点"（isolate the main action），而不是没
> 有选择地空着。当前页属于后者。

### 2.2 每屏信息量太少，撑不起一屏

- 第 2 屏：一个标题 + 三张小卡（每卡只有"编号 + 图标 + 标题 + 一句话"）就占满整屏；
- 第 3 屏：一个 BioOps 孤盒 + 四张一句话卡片；
- 第 4 屏：一句引言 + 一段解释。
卡片本身没有 hover 态、没有连接关系、没有次级信息，视觉重量太轻。

### 2.3 章节节奏单一，全是同一种构图

四段全是"居中 eyebrow 小字 + 居中 大标题 + 居中 副标题 + 居中 卡片组"。没有任何交
替布局（左文右图、不对称、时间线、数字带），没有分区背景变化，没有视觉锚点。视线
没有行走路线，只有重复的原地下坠。

### 2.4 缺"实体内容"，About 页没有立起来的支点

业界转化好的 About 页共同点是：mission + 真实故事/人 + 具体数字（proof）+ 明确的
下一步（next step）。当前页只有概念叙事（Discovery/Execution/Evidence + Ecosystem
+ Vision），没有任何**具体可信的信息**：没有数据指标、没有项目里程碑、没有团队/创
始人信息、没有页脚（导航链接、GitHub、联系方式、版本号、备案）。概念说完了，页面
也就到底了——这是"空"的深层原因。

### 2.5 Hero 按钮与顶部导航职能重复

Hero 区 4 个按钮（开始分析/进入控制台/了解技术架构/GitHub）与顶栏导航、未来页脚
高度重叠。首屏 CTA 应当收敛为一个主行动 + 一个次行动，其余让位给导航/页脚。

### 2.6 BioOps 与四组件缺层级和连接可视化

BioOps（平台集成与科研任务编排层）明明是生态的"底座"，却和一个普通卡片一样大、
孤零零漂着。它与其他四组件（科研寻宝鼠/Polariseq/FlowFrame/BioReport）是"编排层
→ 组件/协议/产物"的层级关系，页面上完全没有表达这层关系。

### 2.7 背景一成不变，放大空旷感

从头到尾同一张深空渐变 + 稀疏星点。分区没有明暗/质感变化，导致每个区块的边界只
能靠文字标题感知，页面显得更长、更散。

## Part 3　优化方案总览（信息架构重排）

页面叙事线（业界 About 页六步叙事的平台版）：

```
Hero（价值主张，CTA 收敛为 1 主 1 次）
  ↓
指标条（Stats band：真实数字一排，立刻"有料"）          ← 新增
  ↓
01→02→03 三步流程（改横向连接时间线，带输入/输出关系）   ← 改造
  ↓
AI4S Ecosystem（改 Bento Grid：BioOps 大底座块 + 四组件小块）← 改造
  ↓
版本历程 / 里程碑时间线                                  ← 新增
  ↓
Vision（We are made of star-stuff. 保留，排版加宽加大）
  ↓
CTA 横幅 + Footer（链接/GitHub/联系方式/版本/备案）      ← 新增
```

- 容器宽度：整体 max-width 提到 1320px（Hero 文案列与 Vision 引言列保持 760~860px
  阅读舒适宽，卡片组全宽铺 1320px）。
- 节奏：相邻 section 交替背景质感（透明 → 微亮玻璃带 → 透明 → 细分隔线 → 深色
  CTA 横幅），section 垂直间距统一为 96px/140px 两档 token。
- 所有新增数字用【】占位，由用户填真实值，**禁止编码 Agent 编造**（比赛晋级、论文
  投稿、数据集数量等只有用户掌握）。

## Part 5　分阶段 Paste-ready 提示词

### 5.1 阶段 P0　布局骨架与节奏

```text
你是一名资深前端工程师。项目使用 Vue3 + Vite（样式体系以现有代码为准）。

任务：在现有「关于」页面（/about 路由对应的视图组件与样式文件，请先自行定位阅读）
基础上做布局优化。先完整阅读现有实现再动手；禁止推倒重写、禁止改路由和功能逻辑、
禁止引入新依赖。

## 逐条修改项

1.【容器宽度】当前所有区块共用一条窄栏（目测 max-width 约 860~1100px），在 2560px
  宽屏下两侧大面积空。处理：
  - 卡片组/网格类容器 max-width 统一提高到 1320px；
  - 纯文字列（Hero 文案、Vision 引言）保持 760~860px 阅读宽度，居中；
  - 页面全局水平内边距统一为 24px（移动端 16px）。

2.【卡片体量】理念卡与生态卡内容单薄、视觉重量过轻。处理：
  - 卡片 padding 从现状加大到 28~32px；
  - 卡片高度对齐（同排等高），卡片内标题与正文字号字重形成两级对比：
    标题 18px/600，正文 14px/400，行高 1.7；
  - 卡片背景从纯透明改为 rgba(255,255,255,0.04) + 1px 边框
    rgba(255,255,255,0.08) + 圆角 16px；
  - hover 态：translateY(-4px)，边框色提亮为 rgba(255,255,255,0.18)，
    阴影 0 8px 24px rgba(0,0,0,0.35)，过渡 250ms ease。

3.【章节节奏】全页构图单一（全是居中标题+卡片组），背景从头到尾同一张渐变。
  处理：
  - section 垂直间距统一成两档 token：紧凑 96px、宽松 140px，替换现状参差不齐
    的间距；
  - 交替背景质感：第 2 屏（01 02 03）和第 4 屏（Vision）保持透明底；生态区
    加一条通栏微亮玻璃带（background: rgba(255,255,255,0.03)；
    backdrop-filter: blur(8px)），上下用 1px rgba(255,255,255,0.08) 细线收边；
  - eyebrow 小字（如 FROM QUESTION TO EVIDENCE）统一字号 13px、字间距
    0.2em、颜色 rgba(255,255,255,0.55)；章节大标题统一 36px/700。

4.【动效约束】上述 hover 与过渡只用 transform/opacity；尊重
  prefers-reduced-motion（开启时去掉位移，保留颜色反馈）。

## 全局约束

- 整体风格与平台首页一致，保留星空渐变基调与全部现有文案；
- 不改动任何文字内容，不改组件逻辑；
- 响应式不破：1320px 容器在 ≤1366px 屏宽下按屏宽自适应，移动端单列无横向滚动。

## 验收（逐条自检并简述改动文件与关键属性）

- [ ] 卡片组容器 max-width 1320px，纯文字列 760~860px
- [ ] 卡片 padding/字号/hover 四件套落地
- [ ] 生态区出现玻璃带与细线收边，章节间距成两档
- [ ] 桌面 2560px 与 1366px、移动端 375px 三档宽度无布局破损
- [ ] 页面功能行为与改前完全一致
```
