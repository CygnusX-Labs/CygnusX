# CygnusX Frontend v2.0 - W09 变更报告

- 状态：部分完成。报告 taskId 深链、流程监控连接文案及常规页间距已修正；WebSocket 断线、过滤和报告预览的端到端验收待补。
- 基线与保护：沿用 W00 基线，保留起点五个脏子模块、原规范及 W01–W08 改动。
- 采用规范：实施规范 §5.7–§5.9、§19 W09；活动 `CygnusX_frontend.md` 表格/布局/报告约束。
- 根因核实：报告列表 API 的 `keyword` 只搜索标题、流程名和描述，不搜索 `task_id`；旧页面将任务深链 `taskId` 写进 `keyword`，关联报告通常无法显示。后端报告列表仍为现有合同，本批不改 API。
- 实际修改：报告页按既有列表 API 每页 200 条查找匹配 `task_id`，在普通列表上方展示关联报告；深链变化时用请求序号防止旧结果覆盖。普通列表筛选不再被 taskId 强制覆盖。流程监控在模板尚未加载时显示“连接未建立”。仪表板、报告、项目和流程监控页移除与 DefaultLayout 重叠的内层 padding，活动架构文档同步。
- 自动验证：`npm run type-check`、`npm run build`、`git diff --check` 通过。W00 全量 Vitest 基线已有 7 个失败，尚未重新对照。
- 视觉与业务证据：未取得；浏览器限制见 W00。报告深链/筛选、WS 断线与轮询、任务表多状态需真实后端和浏览器验证。
- 风险与可逆性：深链查找在报告很多时会顺序分页读取，最坏情况下遍历当前用户全部非 Studio 报告；后续若 API 增加 `task_id` 精确过滤可替换。回滚本批涉及 ReportsView、WorkflowMonitorView 和本批次容器 CSS。
- 下一推荐包：W10；同时补 W00–W09 的视觉与交互证据。
