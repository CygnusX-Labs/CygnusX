# 快速入门 —— 欢迎来到 OmicHub

欢迎使用 **OmicHub** 实验室知识库！

这是一份面向新用户的快速上手指南。无论你是第一次登录平台，还是准备提交第一个分析任务，都可以从这里开始了解 OmicHub 的**平台理念**、**各模块的使用方法**，以及遇到问题时该如何排查。

## 写在前面：我们与数据、与宇宙的关系

在做生命科学研究时，我们常常面对的是海量的测序数据、复杂的统计模型和漫长的分析流程。但请不要忘记，这些数据的源头——每一个碱基、每一个细胞、每一个样本——都来自和我们自身一样的星尘。

OmicHub 的设计初衷，正是希望让研究人员能够更专注地「借用」这些原子与数据，去探索生命的本质，而不是被繁琐的运维、配置和命令行所困扰。平台把复杂的组学分析流程封装成可点击、可追踪、可复用的工具，让研究者可以像阅读文献一样轻松地完成从原始数据到发表级结果的全过程。

**OmicHub 的核心理念可以概括为三点：**

1. **让数据回归科学，让人回归思考**：把重复、机械、易错的工程操作交给平台，让研究者把精力放在科学问题本身。
2. **过程可复现，结果可审计**：每一次分析都基于 Snakemake 流程和参数快照，确保实验可复现、可追溯。
3. **知识沉淀与共享**：平台不仅是分析工具，更是实验室集体经验的载体，知识库、流程模板、AI 助手共同构成可传承的研究基础设施。

## 什么是 OmicHub

**OmicHub** 是华中农业大学园艺林学学院自研的**私有化多组学分析平台**，面向生命科学研究团队提供一站式的测序数据分析、任务调度、结果可视化和 AI 辅助研究能力。

平台核心定位：

- **私有化部署**：数据不出内网，适合对数据安全有严格要求的实验室。
- **流程化分析**：内置多种主流组学流程，基于 Snakemake 实现可复现、可扩展的分析。
- **Web 化操作**：无需精通命令行，通过浏览器即可完成上传、配置、运行和下载。
- **AI 辅助**：集成大模型聊天助手，可辅助代码、文献、流程理解和结果解读。
- **知识沉淀**：实验室知识库用于沉淀流程文档、使用经验、培训资料和架构说明。

### 技术栈概览

| 层级 | 技术 |
|------|------|
| 后端 | FastAPI + SQLAlchemy 2.0 + PostgreSQL 14+ + Redis 7+ + Celery |
| 前端 | Vue 3 + TypeScript + Vite + Naive UI + Pinia |
| 流程引擎 | Snakemake 8.0+ |
| AI 能力 | Cherry Studio SSE 架构 + Kimi / OpenAI 兼容 API + MCP SDK |
| 部署 | Docker Compose（Web 主栈 + 独立 Worker 栈） |

## 首次使用：四步上手

### 第一步：登录平台

首次部署完成后，系统会开放 `/setup` 初始化页面，允许创建第一位管理员账号。

- 访问地址：`http://<服务器IP>:8888/setup`
- 该页面仅在系统中没有任何管理员账号时可用，创建成功后自动关闭。
- 后续普通用户需由管理员在「系统管理 → 用户管理」中创建，或在开启自助注册后通过登录页注册。
- 登录地址：`http://<服务器IP>:8888/login`

首次登录后，系统会弹出迎新引导，并发送一条欢迎通知，提示你前往「实验室知识库」查看更多资料。

### 第二步：准备并上传数据

进入「数据管理」页面，上传你的原始测序数据或样本信息文件。

- 支持的常见格式：`*.fastq.gz`、`*.fq.gz`、样本信息表（CSV / Excel）等。
- 平台使用宿主目录 `/data/omichub` 作为统一任务数据目录，Web 服务与 Worker 计算节点共享该目录。
- 建议在上传前按照「数据目录结构说明」整理好样本目录，便于流程自动识别配对文件。

> 💡 小技巧：如果是批量样本，可以联系管理员提前将数据放到共享目录，再在平台上做注册，避免通过浏览器大文件上传。

### 第三步：选择并提交分析流程

进入「分析流程中心」，浏览平台内置的流程：

- **RNA-seq**：转录组差异表达、功能富集、火山图等。
- **ATAC-seq**：染色质开放性分析、Peak  calling、 motif 分析等。
- **ChIP-seq**：蛋白-DNA 互作分析。
- **单细胞测序**：细胞聚类、降维、标记基因分析。
- **全基因组测序（WGS）**：变异检测、注释等。

选择流程后，按页面提示填写参数，例如：

- 参考基因组版本
- 分组信息
- 差异比较方案
- 输出目录

确认无误后点击「提交任务」，平台会生成一个 Snakemake 工作流并分发到 Celery Worker 执行。

### 第四步：监控任务与下载结果

进入「任务中心」，你可以实时查看任务状态：

| 状态 | 含义 |
|------|------|
| 等待中 | 任务已提交，正在排队 |
| 运行中 | 流程正在执行 |
| 成功 | 分析完成，可下载结果 |
| 失败 | 执行异常，需要排查 |

点击任务列表中的「详情」按钮，可查看：

- 实时日志（Snakemake 运行输出）
- 参数快照
- 结果文件列表
- 资源使用情况

任务成功后，结果文件会保存在任务输出目录中，可直接在页面下载，或进入文件浏览器在线预览。

## 核心模块详解：理念与使用方法

下面按照平台主界面从左到右、从数据到结果再到辅助工具的顺序，逐一介绍每个核心模块的**设计理念**和**具体使用方法**。

---

### 1. 数据管理

#### 平台理念

数据是组学研究的起点，也是最容易出现混乱的环节。OmicHub 的数据管理模块坚持「**一份数据、多处复用、统一入口**」的理念：所有原始数据、中间结果、参考基因组和样本信息都集中存放在平台统一管理的目录中，避免散落在个人电脑或服务器各个角落；同时，数据管理与任务系统深度联动，用户在提交任务时可以直接点选数据，而无需手动输入路径。

这一模块体现了 OmicHub「**让数据资产化**」的设计目标——数据不只是文件，而是带有元信息、可被检索、可被复用的实验室资产。

#### 使用方法

1. 登录后点击左侧导航「数据管理」。
2. 在目录树中选择目标目录，点击「上传文件」或「新建文件夹」。
3. 上传完成后，可右键文件进行重命名、移动、下载或删除。
4. 如果是样本数据，建议按照「数据目录结构说明」中的规范命名，例如：
   ```
   /data/omichub/projects/2025_rna_seq/
   ├── raw/
   │   ├── sample_A_1.fastq.gz
   │   ├── sample_A_2.fastq.gz
   │   └── sample_B_1.fastq.gz
   └── sample_info.csv
   ```
5. 在「样本管理」子页面（如已启用）中，可将文件与样本 ID、分组信息、处理条件等元数据绑定。
6. 提交分析任务时，在参数选择页面直接点选已上传的数据目录或样本信息表。

#### 注意事项

- 大文件上传受 Nginx 和浏览器限制，建议超过 5 GB 的文件通过服务器本地拷贝。
- 删除操作通常不可恢复，请谨慎操作重要原始数据。
- 数据目录权限由管理员统一控制，普通用户请勿越权访问他人项目目录。

### 2. 分析流程中心

#### 平台理念

分析流程中心是 OmicHub 的核心能力入口，体现了平台「**流程即代码，流程即服务**」的理念。所有分析流程都基于 Snakemake 构建，具有声明式、可复现、可扩展的特点。管理员可以通过修改 YAML 配置文件或新增流程代码来扩展新的分析类型，而普通用户只需要在网页上填写参数，就能调用这些经过封装和验证的专业流程。

这一模块的目标是让实验室的**最佳实践被沉淀下来**，而不是每个人重复造轮子。

#### 使用方法

1. 点击左侧导航「分析流程中心」。
2. 在流程列表中浏览当前可用的流程卡片，可按研究方向筛选（如转录组、表观组、单细胞）。
3. 点击流程卡片进入详情页，阅读流程说明、输入要求、输出结果和参数说明。
4. 点击「新建任务」，进入参数配置页面：
   - 选择输入数据目录或样本信息表。
   - 选择参考基因组版本。
   - 设置分组与差异比较方案。
   - 设置输出目录和任务名称。
5. 点击「提交任务」，平台会生成 Snakemake 工作流并进入任务队列。

#### 注意事项

- 不同流程对输入格式要求不同，请务必先阅读流程详情页的「输入要求」。
- 参数配置完成后，平台会保存为「参数快照」，可在任务详情中回看。
- 管理员可在后台通过 YAML 配置新增流程，普通用户如需新流程请联系管理员。

---

### 3. 任务中心与监控

#### 平台理念

任务中心体现了 OmicHub「**透明、可控、可追溯**」的执行理念。在传统的命令行分析中，用户往往需要手动查看日志、管理进程、判断任务是否成功；而在 OmicHub 中，每一个任务的完整生命周期——从提交、排队、运行、成功/失败到结果归档——都被可视化地呈现出来。

这一模块让计算资源的消耗变得透明，也让团队协作变得更加高效：导师可以查看学生任务进度，管理员可以监控资源使用，任何人都可以基于历史任务复现分析。

#### 使用方法

1. 点击左侧导航「任务中心」。
2. 在任务列表中查看所有任务的状态、提交时间、流程类型和当前进度。
3. 点击任务行进入「任务详情」：
   - **概览**：查看任务参数、输入输出路径、执行时长。
   - **实时日志**：查看 Snakemake 的实时运行输出，可用于排查失败原因。
   - **结果文件**：浏览并下载分析结果。
   - **资源监控**（如启用）：查看 CPU、内存、磁盘使用情况。
4. 对于失败的任务，可点击「重试」重新执行，或点击「取消」终止正在运行的任务。
5. 任务完成后，可在结果页面点击「下载全部」打包下载，或单独下载某个文件。

#### 注意事项

| 状态 | 说明 |
|------|------|
| 等待中 | 任务已入队，正在等待 Worker 资源 |
| 运行中 | Worker 正在执行 Snakemake 流程 |
| 成功 | 流程正常结束，可查看和下载结果 |
| 失败 | 流程执行异常，请查看实时日志排查 |
| 已取消 | 用户或管理员手动取消了任务 |

- 如果任务长时间处于「等待中」，请检查 Worker 栈是否已启动、Redis 是否可用。
- 任务日志保留时间由管理员配置，重要任务的日志请及时保存。

### 4. AI 聊天助手

#### 平台理念

AI 聊天助手体现了 OmicHub「**智能增强科研**」的理念。大语言模型不会替代科学家的判断，但它可以极大地降低信息获取和代码理解的门槛：帮你快速理解一个陌生的分析步骤、解释一段报错日志、总结一篇文献，甚至协助你撰写结果描述。

平台采用 **Cherry Studio SSE 架构**，支持逐 token 流式输出，让长回复的体验更接近真实对话。同时，通过助手系统和技能注入，AI 能够理解 OmicHub 平台本身的能力边界，从而给出更贴合上下文的回答。

#### 使用方法

1. 点击左侧导航「AI 助手」或顶部聊天图标进入对话界面。
2. 在助手选择区切换不同助手：
   - **通用助手**：日常问答、概念解释。
   - **RNA-seq 助手**：转录组分析相关问题。
   - **单细胞助手**：单细胞测序分析相关问题。
   - **代码助手**：Snakemake、R、Python 代码解释与调试。
   - **文献助手**：文献摘要、方法描述、结果解读。
   - **可视化助手**：图表选择、配色、结果展示建议。
3. 在输入框中输入你的问题，例如：
   - "RNA-seq 中 DESeq2 的 normalized count 和 TPM 有什么区别？"
   - "解释这段 Snakemake 报错的含义：..."
   - "帮我写一段 ATAC-seq Peak 注释的 R 代码。"
4. 等待模型流式输出回复，可在对话中继续追问。
5. 管理员可在后台配置新的 AI Provider、自定义助手和技能（Skill）。

#### 注意事项

- AI 助手需要管理员先配置 AI Provider（`data/ai_providers.yaml` 或 `.env` 环境变量）才能使用。
- AI 生成内容仅供参考，关键分析结论需由研究者自行验证。
- 请不要向 AI 输入涉及隐私或未脱敏的样本信息。

### 5. 实验室知识库

#### 平台理念

实验室知识库体现了 OmicHub「**把经验留下来，把门槛降下去**」的理念。一个实验室最重要的资产不仅是服务器和代码，更是成员积累的使用经验、踩过的坑、形成的规范。知识库就是用来沉淀这些隐性知识的场所。

知识库文章分为两类：

- **内置文档**：由 `docs/knowledge/meta.yaml` 定义，文件存放在 `docs/knowledge/` 目录下，随平台代码版本发布。适合相对稳定的内容，如平台介绍、数据规范、架构说明。
- **在线编辑文档**：可在网页端直接新增、编辑和保存，内容会同步持久化到 `docs/knowledge/` 目录与 `meta.yaml` 中。适合动态更新的实验记录、培训笔记、经验分享。

#### 使用方法

1. 点击左侧导航「实验室知识库」进入文章列表页。
2. 在左侧目录中按分类浏览文章，点击标题查看内容。
3. 如果具有编辑权限，可以点击「编辑」按钮在线修改文章内容：
   - 填写文章标题、分类、ID。
   - 使用 Markdown 编写正文。
   - 点击「保存」，内容会同步写入文件系统。
4. 新建文章时，点击「新建」按钮，填写 ID（英文唯一标识）、标题、分类和正文。
5. 文章保存后，系统会自动更新 `meta.yaml` 索引并同步到前端列表。

#### 注意事项

- 文章 ID 必须唯一，不能与已有内置文档或在线文档冲突。
- 如果在网页端保存时提示「文档不存在」，可能是该文档尚未被索引到数据库，请联系管理员执行索引同步。
- 如果网页端只显示部分文章，请尝试刷新页面，或检查 `meta.yaml` 与后端索引是否一致。
- 建议定期备份 `docs/knowledge/` 目录，防止在线编辑内容丢失。

### 6. 云端沙盒终端

#### 平台理念

云端沙盒终端体现了 OmicHub「**保留灵活性，但不过度依赖命令行**」的理念。虽然平台努力将常用操作 Web 化，但在实际科研中，总有一些临时性的调试、查看、验证工作需要命令行。云端终端提供了一个受控的 Web 命令行入口，让用户无需 SSH 登录服务器即可快速完成这些操作。

这一模块既保证了操作的便捷性，又通过权限控制和操作审计降低了安全风险。

#### 使用方法

1. 点击左侧导航「云端终端」或顶部工具栏中的终端图标。
2. 系统会在浏览器中打开一个 Web Shell，连接到一个隔离或半隔离的运行环境。
3. 在终端中执行常见命令，例如：
   ```bash
   # 查看数据目录
   ls /data/omichub/projects/

   # 查看某个任务的工作目录
   cd /data/omichub/tasks/<task_id> && ls -l

   # 快速查看文件内容
   head -n 20 sample_info.csv
   ```
4. 使用完毕后点击「关闭」或保持会话（会话超时由管理员配置）。

#### 注意事项

- 云端终端需要管理员授予相应权限，未授权用户无法使用。
- 请勿在终端中执行破坏性操作，如 `rm -rf /`、修改系统配置等。
- 终端会话通常会有超时限制，长时间不操作会自动断开。
- 所有命令行操作可能会被记录用于审计，请遵守实验室安全规范。

### 7. 饼干积分与计费

#### 平台理念

饼干积分机制体现了 OmicHub「**公平使用计算资源**」的理念。在一个共享的实验室平台中，计算资源是有限的，如果没有合理的分配机制，很容易出现少数人占用大量资源、多数人排队等待的情况。通过「饼干」这一虚拟货币，平台把计算资源的消耗量化出来，让每个人都对自己的资源使用有清晰的认知。

同时，饼干机制也帮助实验室管理者评估不同任务类型的真实成本，为后续硬件扩容和流程优化提供数据支持。

#### 使用方法

1. 点击右上角头像，进入「个人中心」。
2. 在「我的饼干」页面查看当前余额、消费记录和获取记录。
3. 提交分析任务时，系统会根据流程类型和预估资源消耗显示「所需饼干」。
4. 任务执行完成后，系统会根据实际 CPU、内存、运行时长扣除相应饼干。
5. 管理员可在「系统管理 → 饼干管理」中：
   - 为用户充值饼干。
   - 配置不同流程的定价策略。
   - 查看全局饼干消耗统计。

#### 注意事项

- 初次部署后，管理员需执行 `make init-cookies` 初始化默认定价策略。
- 如果饼干余额不足，可能无法提交新任务，请联系管理员充值。
- 饼干仅用于平台内部资源核算，不具备实际货币价值。

### 8. 富集分析与可视化

#### 平台理念

富集分析与可视化模块体现了 OmicHub「**让结果可解释、可展示**」的理念。组学分析的最终目的不是产生一堆表格，而是从数据中提取生物学洞见。通过 GO / KEGG 富集、火山图、热图、PCA 等常用可视化工具，平台帮助研究者快速定位关键基因、通路和样本关系，并将结果以直观的图表形式呈现出来。

这一模块强调「**分析即沟通**」：结果不仅要自己看得懂，还要能在组会、论文和合作交流中清晰地表达。

#### 使用方法

1. 在任务结果页面找到富集分析或可视化工具的入口（部分流程会自动生成图表）。
2. 点击进入「富集分析」工具：
   - 上传差异基因列表（通常为 CSV 或 Excel）。
   - 选择物种和注释数据库（GO / KEGG）。
   - 设置显著性阈值（如 p-value < 0.05）。
   - 点击「运行分析」。
3. 分析完成后，查看富集结果表格和条形图、点图等可视化。
4. 进入「可视化」工具：
   - 选择图表类型：火山图、热图、PCA、箱线图等。
   - 上传表达矩阵或差异分析结果。
   - 配置颜色、分组、标签等样式参数。
   - 点击「生成图表」。
5. 生成的图表支持在线预览、下载 PNG / PDF / SVG 格式。

#### 注意事项

- 富集分析需要正确的基因 ID 类型（如 Gene Symbol、Ensembl ID），请确认与数据库匹配。
- 可视化工具的输入格式要求见各工具页面的说明文档。
- 生成的图表可用于论文发表，但请根据期刊要求调整分辨率和配色。

### 9. JBrowse 2 基因组浏览器

#### 平台理念

JBrowse 2 基因组浏览器体现了 OmicHub「**从表格到基因组的多尺度观察**」的理念。很多组学分析结果最终需要回归到基因组坐标上观察：一个 Peak 落在哪个基因附近？一个变异位于哪个外显子？一条 reads 的覆盖度如何？通过集成 JBrowse 2，平台让研究者可以在浏览器中直接从表格结果跳转到基因组视图，实现「**所见即所查**」。

#### 使用方法

1. 在任务结果页面找到「在 JBrowse 中打开」按钮（需流程输出包含 BAM、BigWig、BED、GFF 等文件）。
2. 点击后会跳转或弹出 JBrowse 2 浏览器窗口。
3. 在 JBrowse 中：
   - 通过搜索框输入基因名或基因组坐标（如 `chr1:100000-200000`）定位。
   - 在轨道列表中切换显示比对结果、Peak 区域、基因注释等轨道。
   - 缩放、平移查看不同尺度下的基因组特征。
4. 支持导出当前视图截图，用于报告或论文。

#### 注意事项

- JBrowse 2 需要管理员预先配置参考基因组和注释文件。
- 大规模 BAM 文件加载可能较慢，建议使用 BigWig 格式查看覆盖度。
- 不同参考基因组版本的坐标不兼容，请确保分析结果与浏览器使用同一版本。

### 10. MCP 工具扩展

#### 平台理念

MCP（Model Context Protocol）工具扩展体现了 OmicHub「**让 AI 真正理解平台**」的理念。通用大语言模型虽然知识丰富，但它并不了解 OmicHub 内部有哪些数据、任务状态和知识库文章。通过 MCP，平台把自身能力以标准化协议暴露给 AI 助手，让 AI 能够查询知识库、检索任务状态、读取文件元数据，从而给出更精准、更上下文相关的回答。

这一模块代表了平台从「工具集合」向「智能科研助手」演进的未来方向。

#### 使用方法

1. MCP 工具通常由管理员在后台配置和启用。
2. 普通用户在使用 AI 助手时，如果某个问题涉及平台内部信息，AI 会自动调用 MCP 工具获取上下文，例如：
   - 用户问："我的 RNA-seq 任务跑完了吗？"
   - AI 调用 MCP 工具查询任务中心，返回最新状态后生成回答。
3. 管理员可在「系统管理 → MCP 配置」中：
   - 注册新的 MCP Server。
   - 配置工具权限和可访问的数据范围。
   - 测试工具调用是否正常工作。

#### 注意事项

- MCP 工具的可用性取决于管理员是否已正确配置相关 Server。
- AI 通过 MCP 获取的信息受用户权限控制，不会越权访问他人数据。
- MCP 目前仍在持续完善中，部分复杂操作可能仍需要用户手动在页面上完成。

## 常见问题与排查

### 登录后页面空白或加载失败

- 检查浏览器控制台是否有 JavaScript 报错。
- 尝试强制刷新：`Ctrl + Shift + R`。
- 确认 nginx 已挂载最新的 `frontend/dist`，前端更新后需执行 `make docker-reload` 重启 nginx。

### 上传文件失败

- 检查文件大小是否超过 Nginx / 后端上传限制。
- 检查浏览器网络连接是否稳定。
- 如果是大文件，建议联系管理员通过服务器本地目录拷贝。

### 任务提交后一直等待中

- 检查 Worker 栈是否已启动：`docker compose -f deploy/docker/docker-compose.worker.yml ps`
- 检查 Redis 是否正常连接。
- 检查 Worker 日志是否有报错。

### 任务运行失败

点击任务详情中的「实时日志」，重点检查：

- 输入文件路径是否正确
- 样本信息是否完整（如分组、配对关系）
- 参考基因组是否已正确配置
- 工作目录磁盘空间是否充足
- Conda 环境 / 容器镜像是否包含所需软件

### AI 助手无法回复

- 确认管理员已配置 AI Provider（`data/ai_providers.yaml` 或 `.env` 中的 `KIMI_API_KEY` / `OPENAI_API_KEY`）。
- 确认网络可以访问对应的模型 API 服务。
- 检查后端日志中是否有 API 调用失败记录。

### 知识库文章显示不全或保存失败

- 网页端编辑后，确保文章 ID 唯一，不要与 `meta.yaml` 中已有条目冲突。
- 如果提示「文档不存在」，可能是该文档尚未被索引到数据库，联系管理员执行索引同步。
- 知识库内置文档和在线文档的更新机制不同，编辑前请确认自己正在编辑的是哪一类文档。

## 获取帮助

如果在使用过程中遇到问题，可以通过以下渠道获取帮助：

1. **实验室知识库**：阅读相关流程文档和故障排查指南。
2. **API 文档**：访问 `http://<服务器IP>:8000/docs` 查看后端接口说明（开发环境）。
3. **联系管理员**：复杂问题请联系平台管理员或加入实验室内部支持群。
4. **查看日志**：通过 `docker logs omichub-web` 和 `docker logs omichub-worker` 查看后端与 Worker 日志。
