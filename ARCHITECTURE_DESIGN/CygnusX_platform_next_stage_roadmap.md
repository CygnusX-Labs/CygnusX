# CygnusX 平台下一阶段推进路线

> 文档类型：规划 / 目标态，非 as-built。更新日期：2026-10-20。本文不代表功能完成、生产发布或运行门禁通过；具体实现方案与架构调整须逐项设计、评审和验证。

## 1. 方向与现状边界

下一阶段围绕三个相互支撑的方向推进：完善团队协作室，使多智能体真正协作完成科研任务；微调现有记忆系统，提高连续研究中的可靠性；建设科学推理、科学验证和研究演进能力，形成可审阅、可追溯的科研闭环。

现状依据分别为 [Agent 执行框架](CygnusX_agent_execution_framework.md) §5、[记忆架构](CygnusX_memory_architecture.md)、[受控研究计划](CygnusX_research_plan_architecture.md) 与 [科研交付链](CygnusX_research_delivery_architecture.md)。协作室已有 Manager/Worker、Case/Work Item 和事件投影，仍需以真实任务检验完整协作能力；研究计划当前默认关闭且为 PLAN_ONLY，不能视为三项科研能力已经实现。运行验收状态见 [科研功能运行验收](CygnusX_Research_Feature_Runtime_Acceptance.md)。

本路线与根 README 的 M1/M2 衔接：近期先推进协作与记忆基础、科研能力契约设计及 M1 验收；M2 科研阶段正式启动日期仍为 2027-01-01。各方向可增量推进，启用真实执行须满足相应运行门禁。

## 2. 完善团队协作室：实现多智能体协作闭环

目标是让不同职责的 Agent 围绕共同研究目标，完成分工、协作、交叉审阅和交付，贡献与责任均可追溯。

- **职责与分工**：明确 Manager、领域 Agent、Worker 与 QC/交付角色的能力、输入输出和交接条件；计划记录负责人、依赖、预算与验收条件。
- **协作执行**：无依赖任务可受控并行；依赖通过版本化任务和产物引用交接；共享项目上下文，同时隔离各 Agent 的临时工作状态和授权。
- **审阅与分歧处理**：由独立角色复核方法和证据；保存分歧、返工原因及 Manager/专家的裁决，避免把多数意见直接当作科学正确性。
- **持续运行与恢复**：补齐取消级联、暂停/恢复、局部重规划、超时与失败对账；避免重连或重试导致重复副作用，并让房间展示真实后端状态。

验收以一个获批真实科研案例为起点：至少两个不同职责 Agent 形成可核对的任务与产物交接，经过审阅和交付；同时覆盖一条失败恢复或重规划路径。记录各角色贡献、成本、任务状态和证据，并与单 Agent 基线比较质量与协调开销。具体案例与阈值在实施前冻结。

## 3. 微调记忆系统：先可靠，再提升科研连续性

这里的“微调”优先指现有记忆链路、召回策略和治理机制的调整，不预设开展模型权重微调。问题定位参考 [记忆审计与优化路线](CygnusX_memory_optimization_audit.md)；其中审计结论是指定基线的观察，实施前须复核，不能直接认定当前部署仍有全部问题。

| 推进面 | 拟改进内容 | 验收证据 |
| --- | --- | --- |
| 可靠读写 | 检查 embedding 配置、失败可观测性与降级；抽取失败可重试，游标不静默跳过；补齐 block 生命周期和工具闭环 | 真实持久化环境中完成写入、召回、失败重试、修正与遗忘测试 |
| 隔离与治理 | 明确用户偏好、项目研究记忆、Agent 临时上下文的范围；统一授权、开关、来源与保留策略 | 跨用户/项目负例、访问撤销和遗忘后的读取验证 |
| 召回质量 | 调整候选检索、去重、相关性与时间衰减、上下文预算；保留来源与不确定性 | 固定评测集比较相关召回、无关注入、延迟与 token 成本 |
| 跨入口连续性 | 明确 Chat、Studio 文件记忆与 L4 共享上下文的权威来源和同步边界 | 同一项目跨会话/入口可定位相同研究来源，隔离与删除语义一致 |

科研记忆应保存“谁在何时基于什么证据作了什么判断”，并保留反证、修订和失效原因。未经验证的推测不得沉淀为已确立事实；个人偏好记忆也不能替代正式科研记录。

## 4. 建设三项科研能力

| 能力 | 目标 | 拟交付内容 | 验收重点 |
| --- | --- | --- | --- |
| **科学推理（Scientific Reasoning）** | 将科研问题转化为可检验的假设，以及可供科学审阅的研究设计。 | 问题与背景证据、备选假设、可证伪条件、变量与对照、样本/重复、混杂因素、方法适用性、评价指标和专家审阅记录 | 专家能依据明确标准接受、修订或否决设计；缺数据与方法限制显式呈现 |
| **科学验证（Scientific Validation）** | 评估分析结果、方法有效性与科学主张的证据支持程度。 | 输入与方法检查、统计与多重检验审阅、稳健性/独立复核、主张到结果单元格和来源的关联、限制与反证记录 | 区分 supported / contradicted / inconclusive；任务成功、报告生成或引用存在均不直接等于科学主张成立 |
| **研究演进（Research Evolution）** | 保存研究知识，并提出有证据依据的后续研究建议。 | 版本化研究决策与知识、假设修订历史、证据关联、后续研究建议及收益/成本/不确定性说明、停止条件 | 跨轮次可重建判断变化；建议可追溯到证据缺口，经专家审阅后才形成下一版研究计划 |

目标闭环：**科研问题 → 可检验假设 → 研究设计 → 专家审阅 → 受控执行 → 结果与证据评估 → 科学验证 → 知识沉淀 → 后续建议或停止**。证据不足时允许保留不确定结论，不要求每轮都产生新发现。

## 5. 可能涉及的架构调整

以下是待设计的调整候选，不是已存在的数据表、API 或新服务承诺。优先复用现有分层，通过小步契约变更推进。

| 边界 | 调整候选与约束 |
| --- | --- |
| 多智能体编排 | 在既有 Case/Work Item 上完善依赖、责任、交接与审阅状态；明确与 ResearchPlan 的映射，避免多个计划状态各自推进 |
| 科研领域契约 | 评估引入 Hypothesis、Scientific Claim、Validation Result、Research Decision 的版本化契约；定义与 Project、ResearchPlan、Dataset、Task、Manifest/Report 的引用关系 |
| 证据与溯源 | 以可校验的输入、方法/参数/镜像版本、执行记录、产物摘要和结果定位支撑主张；保存审阅者、结论范围及失效/替代关系 |
| 记忆与知识 | 分开个性化记忆和正式研究知识的权威来源；统一项目权限、纠错/遗忘与历史审计之间的规则，再确定存储及索引方案 |
| 工具与执行 | 科学推理和评价经受限工具访问证据；分析仍走声明式 Flow 和受控 Worker；Agent 无 shell、流程 YAML 或 DB 写权限 |
| 前端与观测 | 房间展示角色贡献、交接和失败；项目页展示假设、审阅、证据与演进；状态来自服务器，支持刷新恢复和权限过滤 |

涉及 schema 时必须提供 Alembic 迁移与兼容策略；涉及运行状态时先定义幂等、取消、对账和恢复规则；涉及审批时保持人类 JWT 审批与具体版本/参数绑定。新计划版本不能继承旧审批，模型不能自行批准执行。长任务继续遵守队列与 reconcile-only 边界。

## 6. 推进顺序与交付标准

1. **基线与设计**：复核协作室、记忆审计和科研运行门禁，确定首个真实案例、角色契约、评测集、指标阈值与架构决策；记录外部阻塞条件。
2. **协作与记忆基础**：完成任务交接、审阅、恢复和记忆可靠性/隔离改进，以定向回归与真实持久化验证支撑上线判断。
3. **推理与验证最小科研闭环**：复用受控研究计划与既有计算/交付链，在获批案例上打通假设、专家审阅、受控执行和证据评价；先满足 M1 实际运行要求。
4. **研究演进与多轮评估**：保存研究决策和反证，提出后续方案并经审阅推进下一轮；比较单 Agent、固定流程与多智能体方案，评估质量、可复现性、成本和人工审阅负担。

每阶段分别标明设计完成、代码实现、隔离环境验证和生产准入状态。验收材料包括版本化设计与数据、权限和故障用例、真实运行记录、专家审阅及可重放产物；代码存在或合成测试通过不能替代真实科研验收。改动落地后同步对应 as-built 文档，本文继续作为规划入口维护。
