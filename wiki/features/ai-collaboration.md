# AI 多 Agent 协作

“Overdrive / 超频”是旧文档和接口中的历史称呼；当前能力由意图路由、多专家会诊、请求内子 Agent
扇出和 AgentTeams Case 分别控制，均为受控能力，默认关闭或受部署开关约束。

多 Agent 协作适合需要规划、专业分工、质量复核和交付汇总的复杂任务。它不是 CPU、GPU 或分析
软件的性能加速开关；平台按任务依赖选择最少且合适的 Agent，不会为了展示“团队感”同时启用全部角色。

## 四种协作模式

| 模式 | 机制 | 适用场景 |
| --- | --- | --- |
| Supervisor 主管派工 | Router 选择目标 Agent；Manager 组织会诊；Overdrive 编排图生成计划并聚合 | 目标明确、需要选择最合适专家 |
| Handoff 串行接力 | `transfer_to_agent` 工具 + 白名单校验，同一会话把控制权交给下一个 Agent | 换一个更对口的 Agent 接手整段会话 |
| Map-Reduce 请求内扇出 | `parallel_subagents` 工具，父 Agent 一次提交多个独立子任务，并发执行后汇总 | 秒到分钟级、相互独立、无需中途确认的子任务 |
| Group Chat / Room 讨论 | AgentTeams 协作室，多角色消息、Case、工作项与质量复核 | 跨角色交接、人工审批、长期协作闭环 |

### Supervisor：主管与路由

- 星尘 AI（`agent-router`）用低成本快模型做意图分类，输出结构化路由决策。
- 路由候选和能力描述来自统一能力注册表快照，Chat 侧不自行组装。
- 任何路由失败（模型报错、解析失败、目标不存在）都静默回落到通用助手，不向用户抛错。
- Overdrive 模式使用独立编排图（计划生成 → 计划确认 → 派发 → 汇总），与普通 ReAct 分离。

### Handoff：串行接力

- 仅白名单目标 Agent 可被交接，交接包有长度上限（约 2400 字节）。
- 默认最大跳数 10，达到上限后必须给出最终结果，不能无限转交。
- 源 Agent 收到交接指令后立即结束本轮，由目标 Agent 在同一会话继续，不把控制信号当普通文本回答。

### Map-Reduce：请求内子 Agent 扇出

- 工具 `parallel_subagents`，子循环深度固定为 1，不能再派生子 Agent。
- 子任务并发数、超时、轮数均有上限；每个子循环使用独立数据库会话，失败相互隔离。
- 子循环剥离递归工具、Handoff、协作室创建和记忆写工具；需要人工确认的工具不在子循环执行，
  而是升级回主循环等待用户。
- 由 `SUBAGENT_FANOUT_ENABLED` 或管理端平台设置控制，默认关闭；灰度要求 Agent 同时具备
  `tool_packs` 与 `features.subagents_spawnable` 标记。

### Group Chat / AgentTeams 协作室

- 协作室先判定房间消息意图（聊天 / 澄清 / 工具执行 / Case 执行 / 降级），策略保守，
  宁可漏触发，也不因单个执行关键词误启动真实 Case。
- Case 执行链：房间消息 → 执行意图 → 计划 → Case / 工作项 → Manager / Worker / 质量复核 /
  交付 → 房间时间线投影。
- 内部 A2A 是自研的持久化事件信封 + Redis Streams，不是业界标准 A2A 联邦协议，也不承担普通
  Chat 的 Agent 互操作。
- Bridge 为独立部署进程，必须与平台身份、审批和证据链保持一致；部署与权限未就绪时入口不可用。

## 典型流程

1. 澄清研究目标、数据、约束和交付物；缺少关键资料时先提问。
2. 检索平台知识库，并在必要时补充外部资料，生成可审查计划。
3. 对正式执行、长耗时流程或交付任务请求用户确认；确认只由人类 JWT 写入。
4. 按依赖关系分派执行、质量复核和交付汇总。
5. 展示进度、审批、产物、风险与限制，形成可追溯的最终结果。

## 何时使用

适合多组学项目规划、数据预检与质量门、多个独立调研任务、需要正式分析交付的复杂项目。概念解释、
单一小操作或目标尚不明确的请求，优先使用普通对话或单个专家，更直接也更快。

## 与相关能力的区别

| 能力 | 适用场景 |
| --- | --- |
| 普通 AI 对话 | 问答、解释和轻量建议 |
| 专家路由 | 已明确 RNA-seq、单细胞、代码等任务方向 |
| Handoff | 需要另一个 Agent 接手整段会话 |
| 并行子任务 | 多个彼此独立的小任务，无需中途审批 |
| 受控多 Agent 协作 | 复杂协作、计划、复核和交付 |
| AgentTeams 协作 Case | 跨角色交接、人工审批或长期协作闭环；需部署和权限支持 |

## 使用限制与证据边界

- 可用 Agent、工具、工作台和 AgentTeams 入口由部署配置、权限和会话上下文决定。
- 执行、写入、长耗时任务和正式交付可能要求确认或审批；模型不能代替人类确认。
- 协作过程产生的事件、消息和产物属于过程证据，不代表科研结论或交付已通过验收。
- AI 输出不替代对实验设计、数据质量和研究结论的人工判断。
