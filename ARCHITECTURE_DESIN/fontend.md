# OmicHub 前端视觉与交互规范

> 本文档是 OmicHub 前端样式改动的统一基线。新增页面、组件和局部样式应优先复用既有设计令牌与模式；如确需新增视觉规则，应同时更新本文档和对应的全局令牌。

## 1. 范围与权威来源

| 主题 | 权威实现 | 使用规则 |
| --- | --- | --- |
| 全局令牌、排版、间距、主题变量 | `frontend/src/styles/global.css` | 页面与组件优先使用 CSS 变量，不复制色值或间距常量。 |
| Naive UI 主题覆盖 | `frontend/src/App.vue` | Naive UI 控件通过 `themeOverrides` 统一，不在单个页面重写通用主题。 |
| 主框架、顶部栏、侧边栏 | `frontend/src/layouts/DefaultLayout.vue` | 新增主导航项或壳层细节时遵循现有布局、状态和滚动规则。 |
| 认证页材质与引言 | `frontend/src/views/LoginView.vue`、`frontend/src/views/RegisterView.vue`、`frontend/src/components/StardustQuote.vue` | 认证场景沿用星空、玻璃卡片与克制的提示动效。 |

前端技术栈为 Vue 3、TypeScript、Vite、Naive UI、Tailwind CSS 与 Sass。新 Vue 组件使用 `<script setup lang="ts">`；第三方组件优先使用 Naive UI 与现有 `@vicons` 图标集。

## 2. 设计目标

界面应体现平静、清晰、可靠的科学工作台气质。当前风格以 Apple 设计原则为指导：

- **目的明确**：每个控件应有明确任务，避免为了装饰增加无意义的层级、阴影或动效。
- **立即反馈**：悬停、聚焦和按压在用户操作时立刻反馈；按压反馈默认使用轻微缩放，不等待操作结束。
- **空间一致**：同类组件使用一致的圆角、间距、进入/退出路径和状态颜色。
- **材质分层**：页面背景、玻璃导航、卡片、弹窗按层级区分；玻璃材质不应无节制叠加。
- **克制动效**：普通状态变化使用短过渡；只有手势直接操控的对象才使用可中断、可接续的弹簧动效。
- **可访问性优先**：键盘焦点、减少动效、减少透明度和高对比度设置都是默认交付内容。

## 3. 设计令牌

### 3.1 品牌与语义颜色

| 用途 | 浅色模式 | 深色模式/说明 |
| --- | --- | --- |
| 主色 | `#4C6FFF` | 悬停 `#6381FF`，按下 `#3D5DE6`。 |
| 成功 | `#00B42A` | 深色模式使用 `#22C55E`。 |
| 警告 | `#FF7D00` | 深色模式使用 `#F59E0B`。 |
| 错误 | `#F53F3F` | 深色模式使用 `#EF4444`。 |
| 主文本 | `#1D2129` | `#F2F3F8`。 |
| 次级文本 | `#4E5969` | `#B8BCC8`。 |
| 第三级文本 | `#86909C` | `#7A8194`。 |
| 页面背景 | `#F5F6FA` / `--page-bg: #F7F9FC` | `#0B0F19`。 |
| 卡片背景 | `#FFFFFF` | `#151A25`。 |
| 分隔线/边框 | `#E5E6EB` | `#2A3040`。 |

必须优先使用语义变量：`--neutral-bg`、`--neutral-card`、`--neutral-border`、`--neutral-text-1` 到 `--neutral-text-4`、`--neutral-hover`、`--arco-*`。禁止在业务组件中将浅色模式色值直接复用于深色模式。

图表按 `--kimi-chart-1` 至 `--kimi-chart-6` 的既有顺序取色，不在单张图中引入无语义的新主色。

### 3.2 间距、圆角与阴影

| 类别 | 规则 |
| --- | --- |
| 基础间距 | `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px`，分别对应 `--space-xs` 至 `--space-5xl`。 |
| 页面 | 默认使用 `--page-padding: 32px`；紧凑工具页可使用 `16px`。 |
| 卡片 | 默认内边距 `24px`、卡片间距 `20px`；工具页紧凑卡片可使用 `12px`。 |
| 组件圆角 | 按钮和常规控件 `8px`，小控件 `4px`，卡片 `12px`，大面板/认证卡片可用 `16px`，标签/状态胶囊使用 `9999px`。 |
| 阴影 | 普通浮层使用 `--shadow-soft`；下拉/弹出层使用 `--shadow-dropdown`；不要用重阴影替代层级与留白。 |

只使用上述阶梯组合。相邻模块优先使用 `16px` 或 `20px` 间距，页面区块优先使用 `32px`。避免出现未经说明的 `13px`、`18px`、`26px` 等间距。

### 3.3 排版

字体栈固定为 `Inter, -apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Helvetica Neue, Arial, Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif`。中文页面无需额外切换字体。

| 层级 | 字号/行高 | 字重 | 字距 |
| --- | --- | --- | --- |
| Display | `28px / 36px` | 600 | `-0.02em` |
| 页面标题 | `24px / 32px` | 600 | `-0.02em` |
| 区块标题 | `18px / 28px` | 600 | `-0.01em` |
| 卡片标题 | `16px / 24px` | 500 | 默认 |
| 正文 | `14px / 22px` | 400 | 默认 |
| 小正文 | `13px / 20px` | 400 | 默认 |
| 说明文字 | `12px / 18px` | 400 | 默认 |
| 微型辅助文字 | `11px / 16px` | 400 | 默认 |

大标题使用轻微负字距，小字号不额外压缩字距。文本层级通过字号、字重、行高和色阶共同建立，不能仅靠改变字号。

## 4. 页面与材质层级

### 4.1 基础层级

1. 页面使用 `--neutral-bg` 或业务背景作为最底层。
2. 常规内容放入 `--neutral-card` 卡片；卡片圆角 `12px`，使用克制边框或柔和阴影。
3. 顶部栏、侧边栏、认证卡片等结构层可使用半透明背景与 `backdrop-filter`，以增强层级而非制造装饰。
4. 下拉层、抽屉、弹窗需要比所在内容层更明确的背景、边界与阴影；不要在两层浅色玻璃之间再叠加浅色玻璃。

### 4.2 玻璃材质

主侧边栏当前使用浅色 `rgba(255, 255, 255, 0.56)` 或深色 `rgba(17, 22, 34, 0.62)`，搭配 `blur(24px) saturate(165%)`。认证卡片使用更明显的模糊和轻微顶部内高光，作为独立焦点。

- 玻璃表面必须有足够文本对比度；文本不能使用低对比度灰色。
- 用于结构分区的玻璃层可使用边界或内高光；不要叠加粗边框。
- `prefers-reduced-transparency: reduce` 下移除模糊并回退到 `--neutral-card` 实色背景。

## 5. 组件状态与交互

### 5.1 按钮、可点击项和表单

- 默认圆角 `8px`；主按钮使用品牌主色，成功/警告/错误仅用于对应语义。
- 按压时使用 `transform: scale(0.97)` 和约 `100ms` 的即时反馈；不可使用明显跳动或长时间缩放。
- 常规颜色、阴影、背景和边框状态使用 `140ms` 到 `220ms` 的短过渡。
- 悬停强调应优先使用颜色、背景和轻微阴影；位移通常不超过 `2px`。
- 输入框聚焦使用主色边框与柔和外环，错误提示在字段附近显示，不只依赖全局提示。
- 所有可键盘操作的元素必须保留 `:focus-visible` 焦点环，默认是 `2px solid var(--arco-primary)`，外偏移 `3px`。

### 5.2 卡片

全局卡片状态由 `global.css` 的 `--card-state-duration: 300ms` 和 `--card-state-easing: cubic-bezier(0.4, 0, 0.2, 1)` 统一控制。禁止使用 `transition: all`；背景、边框、阴影、位移与左侧指示器必须分别引用这两个令牌，确保所有卡片以完全相同的节奏切换状态。

- 标准 Naive UI 卡片 `.n-card` 和已有通用卡片 `.arco-card` 自动继承卡片基线。
- 自定义 HTML 卡片根元素必须添加 `.omichub-card`；不能使用 `[class*="card"]` 等宽泛选择器，以免误伤 `card-title`、`card-body` 等内部元素。
- 默认卡片使用 `--neutral-card`、`--neutral-border`、统一圆角，且全高的状态 `border-left` 被还原为普通 `1px` 边框。
- 选中卡片使用 `.is-selected`、`.card--selected`、`.card--active`、`.selected`、`.active`、`aria-selected="true"` 或 `data-selected="true"` 中的一种状态标记。
- 浅色选中态背景为 `rgba(64, 158, 255, 0.05)`，边框为低透明蓝；深色主题使用更可读的深色蓝透明层。
- 左侧指示器由 `::before` 实现：卡片左内边缘 `8px`、宽 `4px`、高 `32px`、完全圆角并垂直居中。默认以 `opacity: 0` 和缩短的 `scaleY` 隐藏；选中时同步过渡到完整高度。未选中悬停时可低透明度预显。
- 文件网格卡和工具卡已接入 `.omichub-card`。新增有选择语义的自定义卡片必须遵循同一契约，不再单独实现左侧高亮边框。

### 5.3 导航与侧边栏

主侧边栏宽度为 `220px`，折叠宽度为 `64px`，最右侧不保留分割边框。展开态导航项高度为 `40px`、圆角 `8px`，并使用 `margin: 0 12px`，使选中背景在滚动边界前收口、完整显示左右圆角；折叠态菜单项取消该额外边距以保持 `40px` 图标触控区域。选中态使用 `--sidebar-active` 和 `--sidebar-active-text`，悬停态使用低强度的主色渐变与轻微内描边。

侧边栏滚动容器是 `.sider-nav-groups`，必须保持以下规则：

- 垂直滚动、横向隐藏，`scrollbar-gutter: stable` 固定保留滚动槽位，禁止因滚动条显隐造成图标和文字横移。
- WebKit 浏览器使用 `6px` 物理宽度、透明轨道、`999px` 圆角滑块；滑块必须使用 `border: 1px solid transparent` 和 `background-clip: padding-box`，将视觉宽度收窄至约 `4px`。
- 默认滑块使用 `rgba(144, 147, 153, 0.05)`；鼠标悬停整个 `.app-sider` 时显示为 `rgba(144, 147, 153, 0.3)`；直接悬停滑块时增强到 `rgba(144, 147, 153, 0.5)`。
- Firefox 使用 `scrollbar-width: thin` 与 `scrollbar-color`，默认和侧边栏悬停状态分别对应 `0.05` 与 `0.3` 透明度，轨道始终透明。原生 Firefox 对滚动条颜色动画及 Thumb 独立悬停支持有限，应接受其无动画回退，不使用 JavaScript 模拟滚动条。

不要在业务组件中编写全局 `::-webkit-scrollbar` 覆盖规则；若某一独立滚动区域有特殊需求，应采用容器限定选择器，并说明是否需要稳定滚动槽位。

### 5.4 认证页与星尘引言

认证页沿用星空背景、居中的玻璃卡片和轻量漂浮感。注册页桌面端最大卡片宽度约 `698px`，用户名/邮箱和密码/确认密码均采用两列布局；窄屏退化为单列。

`StardustQuote` 是可访问的按钮式引言：点击展开或收起；桌面端鼠标离开整段引言区域即收起；触摸设备可再次点击收起。不得恢复固定秒数倒计时，也不能让引言以绝对定位覆盖注册表单。注册页使用 `placement="flow"` 让引言参与文档流。

## 6. 动效规范

全局动效令牌：

```css
--motion-quick: 140ms;
--motion-standard: 220ms;
--motion-spring: cubic-bezier(0.2, 0.8, 0.2, 1);
```

- 普通悬停、颜色、阴影与焦点状态：优先 `140ms` 或 `180ms ease-out`。
- 卡片浮层、导航宽度、面板材质变化：优先 `220ms` 和 `var(--motion-spring)`。
- 可逆动画必须从当前呈现状态继续，进入与退出遵循同一空间路径。
- 非手势交互不使用弹跳、循环位移或长延迟。循环装饰动效必须低频、低对比，并支持减少动效。
- 拖拽、抽屉、底部面板等直接手势交互应使用可中断弹簧：默认临界阻尼、无过冲；只有快速甩动等有速度输入的场景才允许轻微回弹。
- 动画仅优先使用 `transform` 和 `opacity`，避免在动画中频繁改变布局尺寸、阴影层级或大面积滤镜。

## 7. 响应式与可访问性

- 布局先保证内容可读和可操作，再缩减留白；工具页在 `1200px` 以下从三列降为单列。
- 认证页和长表单允许纵向滚动，不得通过固定 `100vh` 与 `overflow: hidden` 裁剪内容。
- 窄屏下两列表单降为单列；点击目标要保留足够触控面积。
- `prefers-reduced-motion: reduce` 下取消循环、漂浮、弹跳和大位移动效，保留极短的颜色/透明度反馈。
- `prefers-reduced-transparency: reduce` 下移除玻璃模糊，使用实色表面。
- `prefers-contrast: more` 下保持或增强焦点环、文本与边界对比。
- 任何仅靠颜色表达的状态都应同时提供图标、文本、位置或 ARIA 语义。

## 8. 实现边界

### 应当做

- 在组件局部样式中复用全局 CSS 变量。
- 使用组件根类名约束样式；需要穿透 Naive UI 内部元素时使用最窄的 `:deep()` 选择器。
- 为深色模式写对应变量或使用现有语义变量。
- 新增可交互组件时同时设计 default、hover、active、focus-visible、disabled、loading 和 error 状态。
- 修改全局模式、令牌或基础组件时同步更新本文档。

### 不应当做

- 不在业务组件中重新定义品牌主色、圆角阶梯、字体栈或全局滚动条。
- 不使用 `transition: all`，不以长时间动画替代响应反馈。
- 不移除键盘焦点环，不以 `outline: none` 取代可访问焦点样式。
- 不在浅色和深色模式共用不可读的固定灰色。
- 不通过隐藏溢出裁剪本应可滚动的表单、表格或移动端内容。

## 9. 前端样式改动清单

提交前逐项确认：

1. 是否复用了 `global.css` 中的色彩、间距、排版、圆角和动效令牌？
2. 浅色与深色主题是否都可读，且 Naive UI 控件是否仍遵循 `App.vue` 主题？
3. hover、active、focus-visible、disabled、loading、error 等状态是否完整？
4. 动效是否即时、短促、可打断，并在减少动效模式下安全回退？
5. 玻璃材质是否只用于结构层，且减少透明度模式下有实色回退？
6. 是否验证了窄屏、长内容和滚动场景，避免遮挡、裁剪与滚动条导致的布局抖动？
7. 是否运行了 `cd frontend && npm run type-check`；涉及构建配置或资源时是否额外运行 `npm run build`？
8. 本文档是否已反映新增或改变的全局视觉规则？
